## 1. 现状分析

### 1.1 老系统数据流

根据 `数据确认与维护出入库模块分析文档.md` 分析，老系统存在**两条独立的数据流**：

#### 数据流 A：数据确认模块（trans.pbl）→ 自动触发维护入库
```
ITSM维护单配件更换完成
    ↓
写入 SM_IN_PART_CHANGE (sys_status=2, operflg=1)
    ↓
CCGL数据确认模块（u_trans_in_ed1.sru）确认
    ↓
更新 SM_IN_PART_CHANGE.sys_status=5
    ↓
自动创建维护入库单（TWH13_IN, invtyp='3'）
    ↓
更新 TMM43_EID（工程师个人仓库 → 正式仓库）
```

#### 数据流 B：维护出入库模块（wh_syc.pbl）→ 手动创建维护入库
```
仓库管理员手动创建维护入库单（w_wh_whin_input.srw）
    ↓
写入 TWH13_IN（invtyp='3'）
    ↓
审核后调用存储过程 USP_WH_IN
    ├─ 更新 TWH13_IN.auditflg='2'（审核标志）
    ├─ 更新 TWH14_CHECKINDT（入库明细）
    ├─ 更新 TWH11_DETAIL（批次库存）
    ├─ 添加 TWH12_MOVEMENT（库存移动记录）
    └─ 如果是EID设备，更新 TMM43_EID.whcd
```

> **说明**：数据流A和数据流B都会创建 invtyp='3' 的维护入库单，但触发方式不同。

### 1.2 新系统现状

| invtyp | 类型 | 关联单据 | 当前实现状态 | 业务来源 |
|--------|------|----------|--------------|----------|
| 1 | 采购入库 | 采购订单号 (TPC10) | ✅ 完整 | 采购模块 |
| 2 | 销售退货入库 | 销售单号/预计划号 | ✅ 基础 | 销售/预计划 |
| 3 | **服务返还入库** | **ITSM工单号** | ⚠️ **需完善联动** | **ITSM维护** |
| 4 | 调拨入库 | 调拨单号 | ✅ 基础 | 仓库内部 |
| 5 | 其他入库 | - | ✅ 完整 | 手动 |
| 6 | 退货出库 | 退货单号 (TPC16) | ✅ 完整 | 采购退货 |
| 7 | 销售出库 | 销售单号 | ✅ 完整 | 销售模块 |
| 8 | 服务领用出库 | ITSM工单号 | ✅ 完整 | ITSM维护 |
| 9 | 调拨出库 | 调拨单号 | ✅ 基础 | 仓库内部 |

### 1.3 关键发现

**invtyp=3 的"服务返还入库"需要重新设计**：
- 老系统中 invtyp='3' 维护入库对应两种场景
  - 场景A：数据确认模块自动触发（ITSM配件变更）
  - 场景B：仓库手动创建
- 新系统中 invtyp=3 被定义为"服务返还入库"，但缺少与 ITSM 配件变更的联动

## 3. 关键联动场景设计

### 3.1 服务返还入库 (invtyp=3) 优化

#### 当前问题
- PB 中点击"入库确认"自动生成维护出库单 + 维护入库单
- 新系统目前只实现了查询，缺少自动生成逻辑

#### 建议方案

```
ITSM维护单配件更换完成
    ↓
写入 TIT25_ACCESSORIES_UPDATE (accessories_update_type = 'CHANGE')
    ↓
CCGL数据确认模块显示待确认记录
    ↓
用户点击"确认入库"
    ↓
【自动生成】维护出库单（服务领用，invtyp=8）
    ├─ 从工程师仓库出库
    ├─ 关联 TIT25.id
    └─ 自动审核（或待审核）
    ↓
【自动生成】服务返还入库单（invtyp=3）
    ├─ 到目标仓库（TIT25.in_wh）
    ├─ 关联 TIT25.id
    └─ 状态：待审核
    ↓
更新 TIT25.in_wh = '已入库'
    ↓
更新 TMM43_EID
    ├─ whcd：工程师仓库 → 目标仓库
    └─ qcflg：'待检'
```

#### 数据表关联

| 表名 | 字段 | 作用 |
|------|------|------|
| **TIT25_ACCESSORIES_UPDATE** | accessories_update_type | 变更类型（CHANGE） |
| **TIT25_ACCESSORIES_UPDATE** | in_wh | 入库标志（未入库/已入库） |
| **TWH13_IN** | refbillid | 关联 TIT25.id |
| **TWH15_OUT** | refbillid | 关联 TIT25.id |
| **TMM43_EID** | whcd | 仓库代码变更 |
| **TMM43_EID** | qcflg | 质检标志 |

### 3.2 调拨出入库联动

#### PB 逻辑
- 先创建调拨出库单 → 再创建调拨入库单（手动选出库单）

#### 建议优化

```
调拨出库单审核通过
    ↓
自动生成调拨入库草稿单
    ├─ invtyp = '4'（调拨入库）
    ├─ refbillid = 调拨出库单号
    ├─ 源仓库 → 目标仓库
    └─ 明细自动复制
    ↓
仓库管理员确认入库
    ↓
审核入库单
```

#### 实现要点

**StockOutService.audit**：
```python
if record.invtyp == '9' and record.auditflg == '2':
    # 调拨出库审核通过，自动生成调拨入库草稿
    StockInService.create(
        invtyp='4',
        whcd=record.target_whcd,  # 目标仓库
```

### 3.3 退货出库库存校验

#### 业务场景
```
采购入库 → 04仓 +10件 MTHH01
    │
    ├─ 生产领料 → 04仓 -8件（库存剩2）
    │
    └─ 退货 RT000011 → 要退3件
           │  退货单校验：已入库10件，可退
           │  但实际库存只剩2件
           └─ 审核出库 → 库存不足被拦截
```

#### 校验逻辑

**创建退货单时**：
- 校验可退余量 = 已入库量 - 已退量
- 防止超量退货

**审核退货出库时**：
- 校验当前仓库实际库存
- 防止货被领走后还能退货

#### 实现要点

```python
# StockOutService.audit
for detail in record.details_prd:
    stock = db.session.query(func.coalesce(func.sum(StockDetail.itemqty), 0)) \
        .filter(StockDetail.whcd == record.whcd, StockDetail.itemcd == detail.itemcd) \
        .scalar() or 0
    if stock < (detail.outqty or 0):
        return {
            "success": False,
            "error": f"仓库 {record.whcd} 物料 {detail.itemcd} 库存不足（当前{stock}，需要{detail.outqty}）",
        }
```

**出库审核时**：
```python

    db.session.query(Eid).filter(
        Eid.itemcd == detail.itemcd, Eid.eid == detail.eid,
```

## 8. 质检出入库场景

### 8.1 场景定位

**质检出库**（`u_wh_qcout`，PB invtyp=5）：采购入库完成后，将货物从采购仓移到质检库，由质检人员领取检验。

**质检入库**（`u_wh_qcin`，PB invtyp=7）：质检完成合格后，将货物从质检库归还到正式仓库。

> 质检库是一个中间仓位，货物在这里暂存等待检验，**不计入正式库存**。

### 8.2 质检出入库流程

```
采购入库完成（invtyp=1）
    ↓
质检出库（invtyp=QC_OUT）
    ├─ 关联采购入库单号（refbillid）
    ├─ 从采购入库仓（如04仓）移出
    ├─ 目标：质检库
    ├─ 出库模式A：批次出库（optyp='PC'）
    │   → 按批次/物料编码操作，不关联 EID
    │   → 写入 TWH16_OUTDT（批次出库明细）
    └─ 出库模式B：EID出库（optyp='ID'）
        → 按设备序列号操作，精确到单台
        → 写入 TWH16_OUTDTEID（EID出库明细）
        → TMM43_EID.whcd 更新为质检库代码
    ↓
质检人员在质检库检验
    ↓
质检结果（TQC10/TQC11）
    ├─ 合格 → 质检入库（invtyp=QC_IN）
    │   ├─ 从质检库移入正式仓库（如01成品仓、02维护仓）
    │   ├─ 批次模式：TWH14_CHECKINDT + 更新 TWH11_DETAIL
    │   ├─ EID模式：TMM43_EID.whcd 更新为正式仓库代码
    │   └─ TMM43_EID.qcflg = '合格'
    │
    ├─ 不合格-退货 → 退货出库（invtyp=6）
    │   → 关联采购退货单（TPC16）
    │
    ├─ 不合格-返修 → 进入返修流程（见第10章）
    │
    └─ 不合格-换货 → 退货 + 新采购订单（组合处理）
```

### 8.3 仓库代码流转

| 阶段 | 来源仓 | 目标仓 | TMM43_EID.whcd | TMM43_EID.qcflg |
|------|--------|--------|----------------|-----------------|
| 采购入库 | — | 04（待检仓） | 04 | 待检 |
| 质检出库 | 04（待检仓） | 质检库（如QC仓） | QC仓代码 | 待检 |
| 质检入库（合格） | 质检库 | 01（成品仓）/02（维护仓） | 01/02 | 合格 |
| 质检不合格 | 质检库 | 不合格品仓 | XX仓代码 | 不合格 |

### 8.4 新系统 invtyp 规划

| PB 标识 | 新系统 invtyp | 类型名称 | 建议关联单据 | 是否自动生成 |
|---------|--------------|---------|------------|------------|
| u_wh_qcout | QC_OUT (10) | 质检出库 | 采购入库单号 | 是（采购入库审核后触发） |
| u_wh_qcin | QC_IN (11) | 质检入库 | 质检结果单号 | 是（质检合格后触发） |

### 8.5 自动联动逻辑

```
StockInService.audit（采购入库审核通过）
    ↓
【自动生成】质检出库草稿单
    ├─ invtyp = QC_OUT
    ├─ refbillid = inbillid（关联入库单）
    ├─ whcd = 质检库代码
    └─ 明细：复制入库明细（含EID）
    ↓
质检模块录入质检结果
    ↓
QcResultService.audit（质检合格审核通过）
    ↓
【自动生成】质检入库草稿单
    ├─ invtyp = QC_IN
    ├─ refbillid = 质检结果单号
    ├─ whcd = 目标正式仓库
    └─ 明细：合格品明细（含EID）
```

## 9. 生产出入库场景

### 9.1 场景定位

**生产出库**（`u_wh_scout`，PB invtyp=15）：仓库向生产线领料，将原材料/配件从仓库移出。

**生产入库**（`u_wh_scin`，PB invtyp=6/06）：生产组装完成，成品入库。

> 生产出库和入库对应 MES 生产工单，通过工单号关联。

### 9.2 生产出入库流程

```
MES 生产工单创建
    ↓
生产出库（invtyp=PROD_OUT）
    ├─ 关联 MES 生产工单号（refbillid）
    ├─ 从原料仓/配件仓移出
    ├─ 批次模式：按物料编码+数量操作
    │   → 适用于散料（电路板、螺丝等）
    │   → 写入 TWH16_OUTDT（批次出库明细）
    └─ EID模式：按设备序列号操作
        → 适用于有 EID 的整机/关键配件
        → 写入 TWH16_OUTDTEID（EID出库明细）
        → TMM43_EID.whcd = None（设备离库）
    ↓
生产线组装
    ↓
整机标签生成（标签管理模块）
    ↓
质检结果（组装质检）
    ↓
合格 → 生产入库（invtyp=PROD_IN）
    ├─ 关联 MES 生产工单号（refbillid）
    ├─ 进入成品仓（如01仓）
    ├─ 批次模式：写入 TWH14_CHECKINDT + 更新 TWH11_DETAIL
    └─ EID模式：写入整机 EID，TMM43_EID.whcd = 01（成品仓）
```

### 9.3 新系统 invtyp 规划

| PB 标识 | 新系统 invtyp | 类型名称 | 关联单据 | 是否自动生成 |
|---------|--------------|---------|---------|------------|
| u_wh_scout | PROD_OUT (12) | 生产出库 | MES工单号 | 否（手动创建） |
| u_wh_scin | PROD_IN (6) | 生产入库 | MES工单号 | 否（手动创建） |

> 当前 MES 模块尚未对接，生产出入库暂时手动创建，refbillid 填写工单号备查。

### 9.4 批次 vs EID 的选择逻辑

| 物料类型 | 出入库模式 | 说明 |
|---------|----------|------|
| 整机（POS等） | EID模式 | 每台都有唯一序列号，必须精确追踪 |
| 关键配件（读卡器等） | EID模式 | 有 EID 的配件需精确追踪 |
| 散料（电路板、线材等） | 批次模式 | 无 EID，按数量批次管理 |
| 包装材料/耗材 | 批次模式 | 无需精确追踪 |

## 10. 返修出入库场景

### 10.1 场景定位

**返修出库**：将质检不合格品或故障设备从仓库移出，送往返修区或外部返修。

**返修入库**：返修完成后重新入库，进入重新质检流程。

> 返修是一个独立的仓位流转闭环，与质检结果直接关联。

### 10.2 返修出入库流程

```
质检不合格 / ITSM判定需返修
    ↓
返修出库（invtyp=REPAIR_OUT）
    ├─ 关联：质检结果单号 或 ITSM维护单号（refbillid）
    ├─ 从当前仓库（质检库/维护仓）移出
    ├─ 目标：返修区（内部返修）或 清空 whcd（外部返修）
    ├─ 批次模式：适用于散料返修
    └─ EID模式：适用于有 EID 的设备（更常用）
        → TMM43_EID.whcd = None（设备送修中）
        → TMM43_EID.qcflg = '返修中'（新增状态）
    ↓
返修处理（内部返修区 或 外部厂家）
    ↓
返修完成
    ↓
返修入库（invtyp=REPAIR_IN）
    ├─ 关联：返修出库单号（refbillid）
    ├─ 进入质检库（重新质检）
    ├─ EID模式：TMM43_EID.whcd = 质检库代码
    └─ TMM43_EID.qcflg = '待检'（重置为待检）
    ↓
重新进入质检流程（见第8章）
```

### 10.3 新系统 invtyp 规划

| PB 标识 | 新系统 invtyp | 类型名称 | 关联单据 | 是否自动生成 |
|---------|--------------|---------|---------|------------|
| — | REPAIR_OUT (13) | 返修出库 | 质检结果单号/ITSM单号 | 否（手动创建） |
| — | REPAIR_IN (9) | 返修入库 | 返修出库单号 | 否（手动创建） |

### 10.4 返修状态对应 TMM43_EID 变化

| 阶段 | TMM43_EID.whcd | TMM43_EID.qcflg | TMM43_EID.sflg |
|------|---------------|-----------------|----------------|
| 质检不合格 | 不合格品仓 | 不合格 | 不可用(9) |
| 返修出库 | None（清空） | 返修中 | 返修(5) |
| 返修入库 | 质检库 | 待检 | 待检(3) |
| 重新质检合格 | 正式仓库 | 合格 | 可用(2) |
