# 区域人员管理与自动派单技术方案

## 1. 背景与目标

### 1.1 问题来源

在派工 Tab（`d_dispatch.srd`）对齐 PB 原版时发现三个问题：

1. **`maintenance_type` 字段无用**：PB `d_dispatch.srd` 只在 SELECT 中查询，Insert 语句从未赋值，重构模型保留该列但从未使用。
2. **自动派单逻辑缺失**：PB `u_itsm_rcwh_ve.sru:549-561` 有雏形（根据 `requester` 自动插入 tit21 记录），但逻辑混乱（`accpectder = requester`，请求人≠分派人）。重构后完全丢失。
3. **区域人员管理功能未重构**：PB `u_mc_area` + `d_mc_area_list` / `d_mc_area_form` / `d_mc_areausers` 三个 DataWindow 管理区域负责人和区域用户，重构后只有空模型，无 API/Service/前端。

### 1.2 目标

- 补全区域人员管理功能（Area CRUD + UserArea 多对多关联管理）
- 实现自动派单逻辑（维护单创建时基于 `store_id → area_cd → Area.usercd` 自动生成派工记录）
- 清理派工 Tab 无用字段

### 1.3 关联 PB 源码

| PB 对象 | 表 | 功能 |
|---------|-----|------|
| `d_mc_area_list.srd` | `tmm46_area` | 区域列表：id、name（划区名）、usercd（区域负责人） |
| `d_mc_area_form.srd` | `tmm46_area` | 区域表单：新增/编辑区域，设置区域负责人 |
| `d_mc_areausers.srd` | `tmc13_users` + `tit06_userarea` | 区域用户关联：勾选用户归属某区域（一个区域多个用户） |
| `u_itsm_rcwh_ve.sru:549-561` | `tit21_maintenance_dispatch` | 自动派单雏形（逻辑混乱，需重构） |


**修改后**：
```python
class UserArea(BaseModel):
    """ITSM 区域人员（TIT06_USERAREA）。"""
    __tablename__ = "tit06_userarea"
    id = db.Column(db.Integer, primary_key=True, autoincrement=True)
    area_cd = db.Column(db.String(20), nullable=False, comment="区域编码（FK→tmm46_area.area_cd）")
    user_cd = db.Column(db.String(6), nullable=False, comment="人员编号")
    __table_args__ = (db.UniqueConstraint("area_cd", "user_cd", name="uq_userarea"),)
```

#### 3.2.2 Alembic 迁移

**迁移脚本**：`migrations/versions/xxxx_fix_userarea_area_id_to_area_cd.py`

**操作**：
1. 若 `tit06_userarea` 有数据：`UPDATE tit06_userarea SET area_cd = (SELECT area_cd FROM tmm46_area WHERE area_id = tit06_userarea.area_id)`
2. 删除旧唯一约束 `uq_userarea`
3. 删除 `area_id` 列
4. 新增 `area_cd` 列（String(20), NOT NULL）
5. 新增唯一约束 `uq_userarea(area_cd, user_cd)`

### 3.6 P1：自动派单逻辑

#### 3.6.1 DispatchService.auto_create

**文件**：`app/services/itsm_service.py`（扩展 `DispatchService`）

**方法签名**：
```python
@staticmethod
def auto_create(maintenance_id: str, store_id: str, creator: str) -> dict[str, Any] | None:
    """维护单创建时自动生成派工记录。
    
    逻辑链：
    1. store_id → 查 tmm22_customers.area_cd
    2. area_cd → 查 tmm46_area.usercd（区域负责人）
    3. 若 usercd 存在，插入 tit21_maintenance_dispatch 记录
    
    Returns:
        派工记录 dict 或 None（无区域负责人时跳过）
    """
```

**实现要点**：
- 查客户 `area_cd`：`SELECT area_cd FROM tmm22_customers WHERE custcd = (SELECT cust_cd FROM tit10_maintenanceday WHERE maintenance_id = :mid)`
- 查区域负责人：`SELECT usercd FROM tmm46_area WHERE area_cd = :area_cd AND useflg = '1'`
- 插入 tit21 记录：`maintenance_id` / `business_operation_id`(调 `gf_insert_business`) / `operator`=creator / `accpectd_group`='A1' / `accpectder`=usercd / `dispatch_time`=now / `create_time`=now / `creator`=creator

#### 3.6.2 调用点

**文件**：`app/services/itsm_service.py`（`MaintenanceDailyService.create` 或对应创建方法）

在维护单创建成功后调用：
```python
record = MaintenanceDailyRepository.create(data, creator)
db.session.commit()
# 自动派单
try:
    DispatchService.auto_create(record.maintenance_id, record.store_id, creator)
except Exception as e:
    logger.warning(f"自动派单失败 maintenance_id={record.maintenance_id}: {e}")
```

**容错**：自动派单失败不阻断维护单创建（try/except 包裹 + 日志告警）。

## 6. 风险与回滚

### 6.1 风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| UserArea 表数据迁移失败 | 区域用户关联丢失 | 迁移前备份 tit06_userarea 表 |
| 自动派单逻辑错误 | 维护单创建时误派单 | try/except 包裹 + 日志告警 + 可配置开关 |
| Area.usercd 指向已删除用户 | 自动派单失败 | 查询时 LEFT JOIN，usercd 无效时跳过 |

### 6.2 回滚

- Alembic 迁移可回滚（`alembic downgrade -1`）
- 自动派单逻辑可通过配置开关禁用
- 前端路由可移除
