# 销售管理（预计划）全链路编排 — 最终实施计划

> 融合 Windsurf 计划 + PB 源码验证 + 讨论修正，替代分散在多个文件中的旧计划。

## 1. PB 源码验证结论

### 1.1 字段语义澄清（关键修正）

PB `plan_cust` 表中多个状态字段含义不同：

| PB 字段 | 实际含义 | 数据值 | 我们的方案 |
|---------|---------|--------|-----------|
| `status` | **计划工作流状态** | 00/01/02/04/09 | → 我们映射到 `plan_status`（统一简化） |
| `plan_status` | **呼出结果** | Y/N/O | → 呼出结果放到 `PLAN_SERVE.serve_back` |
| `imple_status` | 实施状态 | 01/NULL | → 存放下游单据ID（我们在 create 时写入） |
| `serve_status` | 服务状态 | 01/NULL | → 由 PlanServe 表管理 |
| `back_status` | 回退状态 | — | 保留字段 |

**结论**：PB 的 `plan_status` 不是工作流状态。我们统一简化：`plan_cust.plan_status` = 工作流状态，呼出结果放 PlanServe 表。

### 1.2 实际 plan_cust.status 值分布（ortopbitsmdb 生产数据）

```
00  计划中      20 条  (仅 plantyp=30)
01  已确认    8102 条  (绝大多数)
02  实施中     116 条  (仅 plantyp=30)
04  已完成     161 条
09  作废      1209 条
```

**不存在 03 或 05**。所以我们采用 00→01→02→04→09。

## 2. 预计划完整业务流程（最终版）

```
客户部: 新建预计划 ──→ 话务台呼出确认 ──→ 实施计划制定 ──→ 实施确认 ──→ 仓库出库 ──→ 完成
                        │                   │               │            │
状态:                 00 计划中          01 已确认       02 实施中     04 已完成
                        │                   │               │            │
客户:              TEMP 临时           TEMP→PENDING        ↓        PENDING→ACTIVE
                        │                   │               │
PLAN_SERVE:      (待呼出)           创建呼出单        反馈记录
                        │              status=01
下游ITSM:                                          MaintenanceOpen/
                                                   DeviceChange/
                                                   RecycleTask/...
```

### 2.1 各阶段详细说明

| 阶段 | plan_status | 触发动作 | 客户状态 | 后续步骤 |
|------|:--:|------|:--:|------|
| 新建 | `00` | 创建预计划记录 | TEMP | 话务台呼出 |
| 呼出确认 | `00→01` | 创建 PlanServe + 记录呼出结果 | TEMP→PENDING | 制定实施计划 |
| 实施中 | `01→02` | 实施计划已制定 | PENDING | 实施确认 |
| 实施确认 | `02` 不变 | `implement()`: 按 plantyp 生成下游ITSM单据 | PENDING | 仓库设备出库 |
| 已完成 | `02→04` | `complete()`: 设备出库完成 | PENDING→ACTIVE | 终态 |
| 作废 | `→09` | 级联作废下游 + 客户 INVALID | INVALID | 终态 |

## 6. 设计决策记录

| # | 决策 | 理由 |
|---|------|------|
| D1 | plan_status = 工作流状态（非PB的呼出结果） | 统一简化，避免字段语义混淆 |
| D2 | 下游 ITSM 单据在 implement() 生成（非 create()） | 对齐 PB 流程：先呼出确认意向，再实施生成单据 |
| D3 | 状态码用 04 而非 03 表示已完成 | PB 生产数据中不存在 03 |
| D4 | 设备出库为独立手动步骤（OV=1），不在 implement 中自动出库 | 实施确认≠设备离库，仓库需人工审核 |
| D5 | PlanServe 的 status 字段独立管理（00待呼出/01已呼出/09作废） | 不与 plan_cust.plan_status 混淆 |
