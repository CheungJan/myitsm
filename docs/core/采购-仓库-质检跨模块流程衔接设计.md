# 采购-仓库-质检跨模块流程衔接设计

## 一、文档目的

采购管理模块已验收（需求/订单/结算/退货），仓库和质检模块后续开发。本文档梳理采购与下游模块的关联点和注意事项，确保多模块协作时数据可追溯、流程可闭环。

---

## 二、核心关联链路

```
采购需求(PR)    采购订单(PO)     仓库入库(GR)      质检判定(QC)      仓库入库/退货
TPC01/02        TPC12/13        TWH13/14         TQC10/11          TWH13 → 合格入库
    │               │                │                 │              TPC16/17 → 不合格退货
    │  审批锁定额度   │  拆单/并单      │  记录入库量       │  质量结果       │
    │               │  关联需求       │  关联来源订单     │  处理方式       │
    ▼               ▼                ▼                 ▼              ▼
 可用余额         TPC20 LINK       inqty++          qc_result       return/repair
```

### 2.1 关键关联字段

| 表 | 字段 | 作用 |
|----|------|------|
| TPC13 (订单明细) | `ref_pcplanid` + `ref_pclineno` | 回溯来源需求 |
| TPC13 (订单明细) | `inqty` | 已入库数量，实时更新 |
| TPC20 (需求-订单关联) | `pcplanid` + `rgstbillid` + `linkqty` | 多对多关联追踪 |
| TWH13 (入库主表) | `refbillid` | 关联来源单据号（采购订单号） |
| TWH14 (入库明细) | `reflineno` | 关联订单行号（订单号通过主表 TWH13.refbillid 获取） |

## 三、拆单/并单对下游模块的影响

### 3.1 拆单场景

```
需求 PP001: 物料X 150个
    │
    ├──→ 订单 PR001: 供应商甲, X 100个  @¥10
    │         │
    │         └──→ 入库 PC002126: 甲发货, X 60个 → 仓库01
    │
    └──→ 订单 PR002: 供应商乙, X 50个  @¥12
              │
              └──→ 入库 PC002127: 乙发货, X 50个 → 仓库02
```

**仓库入库时**：TWH13.refbillid = 订单号，TWH14.reflineno = 订单行号。追溯供应商和价格需 JOIN TPC12/TPC13。

**质检时**：按入库单检验，每批货的供应商不同，质检结果按批次记录。

**注意事项**：
- 同一物料不同供应商，入库后是不同批次，质检需分别检验
- 退货时需精确到"哪个供应商的哪批货"，通过 `TWH13.refbillid`(订单号) + `TWH14.reflineno`(行号) 定位

### 3.2 并单场景

```
需求 PP001: X 50个
需求 PP002: X 30个
    │
    └──→ 合并订单 PR003: 供应商甲, X 80个  @¥10
              │
              └──→ 入库 PC002128: 甲发货, X 80个
```

**注意事项**：
- 入库时 `inqty` 按订单行更新，不按需求行拆分
- 需求追溯通过 TPC20.linkqty 实现：
  - TPC20 记录 1: PP001 → PR003, linkqty=50
  - TPC20 记录 2: PP002 → PR003, linkqty=30
- 入库完成后，`v_requisition_execution` 视图自动计算每个需求的 `received_qty`

### 3.3 供应商跟踪

```
订单 PR003: 供应商甲, 物料X 80个, 物料Y 20个
    │
    ├──→ 入库批次1: X 50个 (供应商甲, 生产批号 LOT-A001)
    └──→ 入库批次2: X 30个 (供应商甲, 生产批号 LOT-A002)
```

**当前缺失**：TWH14 入库明细没有 `suppliercd` 字段。供应商信息需要 JOIN TPC12 获取。

**建议**：TWH14 入库明细冗余 `suppliercd`，减少追溯时的 JOIN 开销。

## 四、入库关联采购订单

### 4.1 当前状态

```
TPC12 (订单)  ←→  TWH13 (入库主表)  ←→  TWH14 (入库明细)
rgstbillid          refbillid              reflineno (行号)
                    suppcd                 (订单号通过TWH13.refbillid获取)
```

`TWH13.refbillid` = 采购订单号（`invtyp='1'` 采购入库时）。

`TWH14` 入库明细通过 `reflineno` 关联订单行号，订单号通过上级 `TWH13.refbillid` 获取。**注意：TWH14 没有独立的 `ref_rgstbillid` 字段**，退货追溯时需 JOIN TWH13。

### 4.2 入库时需处理

| 操作 | 说明 |
|------|------|
| 更新 `inqty` | TPC13.inqty += 本次入库数量 |
| 更新 TPC20 状态 | 可选：入库后自动更新 linkstatus（ordered → partial_in → completed） |
| 记录批次/供应商 | TWH14 建议冗余 suppliercd / batchno |
| 触发质检流程 | 入库完成后创建质检出库单 |

### 4.3 结算联动

结算的可结算量依赖 `inqty`：

```
COD/MON: 可结算 = inqty - 已结算
PIA/DEP/INS: 可结算 = rgsqty - 已结算
```

所以入库量的准确性直接影响结算。入库时必须正确更新 `inqty`。

## 五、质检流程与采购的关联

### 5.1 PB 老系统流程

```
采购入库 (TWH13) → 质检出库 (移出到质检区) → 标签管理 (生成配件ID)
    → 质检结果录入 (检查结果/对应标签) → 质检入库 (合格品入库)
                                       → 退货处理 (不合格)
                                       → 返修处理 (不合格)
```

### 5.2 与采购的关联点

| 质检步骤 | 关联采购数据 | 说明 |
|---------|------------|------|
| 质检出库 | 采购入库单号 | 从哪个入库批次中抽检/全检 |
| 标签管理 | 物料编码、供应商 | 按供应商+物料生成配件ID |
| 质检结果 | 入库批次、供应商 | 不合格品追溯到供应商 |
| 退货处理 | 采购订单号、供应商 | 创建采购退货单，关联原订单 |

### 5.3 质检实际表结构（以数据库为准）

| 表名 | 中文说明 | 关键字段 | 备注 |
|------|---------|---------|------|
| `TQC10_RESULT` | 质检结果主表 | `qcbillid`, `refbillid`, `optyp`, `useflg` | `optyp=PJ/C1/C2` 配件/成品；`refbillid` 关联来源单据（非 `outbillid`） |
| `TQC11_RESULTEID` | 质检结果明细（EID） | `qcbillid`, `eid`, `itemcd`, `itemtyp`, `qcstatus`, `inqty` | **实际唯一在用的质检明细表** |
| `TQC11_RESULTDT` | 质检结果明细（批次） | `qcbillid`, `itemcd`, `itemtyp`, `qcstatus` | `optyp=YH` 时写入，当前业务从未使用，数据为空 |

### 5.4 质检结果驱动的分支

```
质检结果 (TQC10/11)
    │
    ├── 合格 ──→ 质检入库 (TWH13, invtyp='3') → 进入可用库存
    │
    ├── 不合格-退货 ──→ 创建采购退货单 (TPC16/17) → 关联原订单 → 退货出库
    │
    ├── 不合格-返修 ──→ 创建返修工单 (ITSM) → 返修完成后重新质检
    │
    └── 不合格-换货 ──→ 创建换货流程（暂无此模块，可作为退货+新订单组合实现）
```

### 5.5 质检表需补字段

> ⚠️ **待执行**：以下字段当前数据库尚未添加，待质检模块开发时执行迁移。

```sql
-- TQC11_RESULTEID 质检结果明细增加处理方式
ALTER TABLE tqc11_resulteid ADD COLUMN disposal VARCHAR(10);
-- disposal: 'accept'=合格入库 / 'return'=退货 / 'repair'=返修 / 'replace'=换货

-- 关联采购退货单（退货处理时写入）
ALTER TABLE tqc11_resulteid ADD COLUMN ref_return_id VARCHAR(8);
-- 退货单号，用于追溯"这个质检不合格项生成了哪张退货单"
```

## 六、客户开通预计划（plan_cust）→ 采购需求关联

### 6.1 业务场景

`plan_cust` 是客户开通业务的核心预计划表（非泛指销售预计划），驱动从销售侧到仓库/ITSM的完整开通流程：

```
预计划单(plan_cust)
    │ planno / plantyp / plan_status
    │
    ├── 计划呼出 ──→ send_date 记录，工程师(serve_ercd)指派
    │
    ├── 计划实施 ──→ imple_status / imple_date / imple_result
    │                  设备分配: posid (EID) / pos_item (型号)
    │
    ├── 销售出库 ──→ TWH15 出库单（invtyp='2'销售出库）关联 planno
    │                  设备 EID 绑定到客户
    │
    ├── 新机开通 ──→ TIT13_MAINTENANCE_OPEN（新机开通单，ref: planno）
    │
    └── 客户信息校验/自动生效
           ↓
        TMM 系列：生成客户资产 BOM（客户-设备绑定关系）
        custcd + posid → TMM35_CUST_POS_RL（客户设备关联表）
```

**关键状态字段**：

| 字段 | 含义 | 典型值 |
|------|------|--------|
| `plan_status` | 计划整体状态 | 待呼出/已呼出/已实施 |
| `imple_status` | 实施状态 | 待实施/实施中/已完成/失败 |
| `serve_status` | 服务状态 | 待服务/服务中/已完成 |
| `back_status` | 回访状态 | 未回访/已回访 |
| `custnew` | 是否新客户 | Y/N，决定是否新建客户档案 |
| `solve_type` | 解决方式 | 上门/远程等 |

### 6.2 plan_cust 与采购的关联点

`plan_cust` 需要特定型号设备出库时，若仓库无现货，触发采购需求：

```
plan_cust (planno, pos_item=整机型号)
    │
    ├── 检查成品库存 (TWH11, whcd=成品库, itemcd=pos_item)
    │   有库存 ──→ 直接分配 posid，进入出库流程
    │
    └── 无库存 ──→ 检查配件库存 (tmm41/42 BOM展开)
             │
             ├── 配件充足 ──→ 生产工单 (tms01_work_order) → 组装 → 质检 → 成品入库
             │
             └── 配件不足 ──→ 生成采购需求 (tpc01_pcplan)
                              slbillid = planno（关联来源预计划）
                              pctyp = '12'（订单采购）
                              item_usage = 'sale'
                              │
                              ▼
                           采购订单 → 入库 → 质检 → 可用库存
                              │
                              └── 入库完成 → 生产可领料 → 组装 → posid生成
```

### 6.3 关联字段

| 表 | 字段 | 用途 |
|----|------|------|
| `plan_cust` | `planno` | 预计划单号，作为 `slbillid` 传入采购需求 |
| `plan_cust` | `pos_item` | 所需整机型号，展开 BOM 确定采购配件 |
| `plan_cust` | `posid` | 分配的设备 EID（出库后写入） |
| `tpc01_pcplan` | `slbillid` | 关联来源预计划号（= `planno`） |
| `tpc01_pcplan` | `pctyp` | `'12'` = 订单采购（与预计划强关联） |
| `tpc02_pcplandt` | `item_usage` | `'sale'` = 客户开通备货 |
| `tmm41_bom` | `bomcd` | 整机 BOM 主表 |
| `tmm42_bomdt` | `itemcd`, `bomqty` | BOM 明细：每台整机需哪些配件及数量 |

### 6.4 采购完成后回调

```
采购入库完成 → TPC13.inqty 更新
    │
    └── 触发检查：关联 slbillid 的预计划所需配件是否齐备
        │
        ├── 未齐备 → 继续等待其他采购订单入库
        │
        └── 已齐备 → 通知生产下达工单 (tms01_work_order)
                     生产领料 → 组装 → 整机质检 → 成品入库
                     → plan_cust.plan_status 更新为"待出库"
```

### 6.5 注意事项

- `plan_cust` 目前在 Python 重构数据库中已存在（直接迁移自 PB）,是后续销售/开通模块的重点
- `slbillid` 字段在 `tpc01_pcplan` 中已预留，采购看板可按 `slbillid` 分组追踪预计划执行进度
- 同一预计划可能触发多个采购需求（多个配件缺货），通过 `slbillid` 聚合查询
- BOM 变更后需重新计算配件缺口，不自动重算

## 七、退货出库流程

### 7.1 当前状态

采购退货单审核通过后，目前没有生成出库单。需要仓库模块支持：

```
退货单审核通过 → 生成退货出库单 (TWH15, invtyp='6')
    → 仓库操作员确认出库 → 减少库存
    → 更新 TPC13.inqty（减少已入库量）
```

### 7.2 出库时需处理

| 操作 | 说明 |
|------|------|
| 生成出库单 | TWH15 关联退货单号 (refbillid = return_id) |
| 减少库存 | TWH11/12 库存明细更新 |
| 更新订单入库量 | TPC13.inqty -= 退货出库数量 |
| 更新退货状态 | TPC16 标记为已完成 |

## 八、ITSM 维护返还与回收链路

### 8.1 维护返还入库

ITSM 维护工单完成后，更换下来的旧配件/设备可能需返还仓库：

```
ITSM 维护工单 (TIT10)
    │  维修完成，更换配件
    │
    ├── 新配件领用出库 (TWH15, invtyp='2') — 从仓库领出安装
    │
    └── 旧配件返还入库 (TWH13, invtyp='3') — 退回仓库
         │
         └── 质检判定：
              ├── 可翻新 → 翻新入库 (TWH13, invtyp='6')
              ├── 可回收 → 回收入库 (TWH13, invtyp='7')
              └── 报废   → 报废出库 (TWH15, invtyp='7')
```

### 8.2 关联字段

| 表 | 字段 | 用途 |
|----|------|------|
| TWH13 | `refbillid` | 关联 ITSM 维护工单号 |
| TWH13 | `invtyp` | `3`=服务返还 / `6`=翻新入库 / `7`=回收入库 |
| TIT10 | `maintenance_id` | 维护工单号，供仓库追溯 |

### 8.3 注意事项

- 维护返还入库的物料可能是损坏件，需标记质量状态
- 翻新入库前需经过翻新流程（ITSM 翻新工单），完成后重新入库
- 回收件入库后进入回收库存，与新品库存分开管理
- 返修件不入库，直接进入返修流程（ITSM），修完后再质检

## 九、跨模块数据一致性校验清单

### 9.1 数量校验

| 校验点 | 规则 |
|--------|------|
| 采购入库量 | `inqty ≤ rgsqty`（入库不超过订购） |
| 质检出库量 | `outqty ≤ inqty`（出库不超过入库） |
| 质检入库量 | `inqty ≤ 合格品数量` |
| 退货量 | `rpcqty ≤ inqty - 已退量` |
| 结算量 | `settle_qty ≤ 可结算余量` |

### 9.2 供应商追溯

```
需求 → 订单(供应商甲) → 入库(批次A) → 质检(批次A结果) → 退货(退给供应商甲)
  │                      │
  └── 订单(供应商乙) → 入库(批次B) → 质检(批次B结果)
```

关键：整个链路中 `suppliercd` 保持传递，不丢失。

### 9.3 状态同步

| 事件 | 更新 |
|------|------|
| 入库完成 | TPC13.inqty++, TPC20.linkstatus 更新 |
| 质检合格入库 | 库存增加 |
| 退货出库 | TPC13.inqty--, 库存减少 |
| 返修完成 | 重新进入质检流程 |

## 十、后续实施建议

### 阶段1：仓库退货出库（配合采购退货）
- 退货审核通过 → 自动生成出库单
- 出库确认 → 减少库存 + 更新订单 inqty

### 阶段2：仓库入库增强
- 入库时记录 `ref_rgstbillid` + `ref_rgstlineno`
- TWH14 冗余 `suppliercd`
- 入库后自动更新 TPC13.inqty

### 阶段3：质检模块
- 补 `disposal` 字段
- 不合格品 → 自动关联创建退货单
- 返修品 → 创建 ITSM 返修工单

### 阶段4：整机生产
- 生产出库 → 质检(整机标签) → 生产入库
- 整机组装完成后生成整机 EID

### 阶段5：全链路测试
- 按 PB 老系统 13 步完整流程走通
- 验证拆单/并单/多供应商场景的数据一致性
