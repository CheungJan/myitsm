# 采购-仓库-质检跨模块流程衔接设计

## 一、文档目的

采购管理模块已验收（需求/订单/结算/退货），仓库和质检模块后续开发。本文档梳理采购与下游模块的关联点和注意事项，确保多模块协作时数据可追溯、流程可闭环。

---

## 二、核心关联链路

```
采购需求(PR)    采购订单(PO)     仓库入库(GR)      质检判定(QC)      仓库入库/退货
TPC01/02        TPC12/13        TWH13/14         TQC01/02/03       TWH13 → 合格入库
    │               │                │                 │              TPC16/17 → 不合格退货
    │  审批锁定额度   │  拆单/并单      │  记录入库量       │  质量结果       │
    │               │  关联需求       │  关联来源订单     │  处理方式       │
    ▼               ▼                ▼                 ▼              ▼
 可用余额         TPC20 LINK       inqty++          qc_result       return/repair
```

### 2.1 关键关联字段

| 表 | 字段 | 作用 |
|----|------|------|
| TPC13 (订单明细) | `ref_pcplanid` + `ref_pclineno` | 回溯来源需求 |
| TPC13 (订单明细) | `inqty` | 已入库数量，实时更新 |
| TPC20 (需求-订单关联) | `pcplanid` + `rgstbillid` + `linkqty` | 多对多关联追踪 |
| TWH13 (入库主表) | `refbillid` | 关联来源单据号（采购订单号） |
| TWH14 (入库明细) | `ref_rgstbillid` + `ref_rgstlineno` | 关联订单行 |

## 三、拆单/并单对下游模块的影响

### 3.1 拆单场景

```
需求 PP001: 物料X 150个
    │
    ├──→ 订单 PR001: 供应商甲, X 100个  @¥10
    │         │
    │         └──→ 入库 PC002126: 甲发货, X 60个 → 仓库01
    │
    └──→ 订单 PR002: 供应商乙, X 50个  @¥12
              │
              └──→ 入库 PC002127: 乙发货, X 50个 → 仓库02
```

**仓库入库时**：TWH14.inbillid 关联 `rgstbillid` + `lineno`，可以追溯到具体供应商和价格。

**质检时**：按入库单检验，每批货的供应商不同，质检结果按批次记录。

**注意事项**：
- 同一物料不同供应商，入库后是不同批次，质检需分别检验
- 退货时需精确到"哪个供应商的哪批货"，通过 TWH14.ref_rgstbillid 定位

### 3.2 并单场景

```
需求 PP001: X 50个
需求 PP002: X 30个
    │
    └──→ 合并订单 PR003: 供应商甲, X 80个  @¥10
              │
              └──→ 入库 PC002128: 甲发货, X 80个
```

**注意事项**：
- 入库时 `inqty` 按订单行更新，不按需求行拆分
- 需求追溯通过 TPC20.linkqty 实现：
  - TPC20 记录 1: PP001 → PR003, linkqty=50
  - TPC20 记录 2: PP002 → PR003, linkqty=30
- 入库完成后，`v_requisition_execution` 视图自动计算每个需求的 `received_qty`

### 3.3 供应商跟踪

```
订单 PR003: 供应商甲, 物料X 80个, 物料Y 20个
    │
    ├──→ 入库批次1: X 50个 (供应商甲, 生产批号 LOT-A001)
    └──→ 入库批次2: X 30个 (供应商甲, 生产批号 LOT-A002)
```

**当前缺失**：TWH14 入库明细没有 `suppliercd` 字段。供应商信息需要 JOIN TPC12 获取。

**建议**：TWH14 入库明细冗余 `suppliercd`，减少追溯时的 JOIN 开销。

## 四、入库关联采购订单

### 4.1 当前状态

```
TPC12 (订单)  ←→  TWH13 (入库主表)  ←→  TWH14 (入库明细)
rgstbillid          refbillid              ref_rgstbillid
                    suppcd                 ref_rgstlineno
```

`TWH13.refbillid` = 采购订单号（`invtyp='1'` 采购入库时）。

`TWH14` 入库明细通过 `ref_rgstbillid` + `ref_rgstlineno` 关联订单行。

### 4.2 入库时需处理

| 操作 | 说明 |
|------|------|
| 更新 `inqty` | TPC13.inqty += 本次入库数量 |
| 更新 TPC20 状态 | 可选：入库后自动更新 linkstatus（ordered → partial_in → completed） |
| 记录批次/供应商 | TWH14 建议冗余 suppliercd / batchno |
| 触发质检流程 | 入库完成后创建质检出库单 |

### 4.3 结算联动

结算的可结算量依赖 `inqty`：

```
COD/MON: 可结算 = inqty - 已结算
PIA/DEP/INS: 可结算 = rgsqty - 已结算
```

所以入库量的准确性直接影响结算。入库时必须正确更新 `inqty`。

## 五、质检流程与采购的关联

### 5.1 PB 老系统流程

```
采购入库 (TWH13) → 质检出库 (移出到质检区) → 标签管理 (生成配件ID)
    → 质检结果录入 (检查结果/对应标签) → 质检入库 (合格品入库)
                                       → 退货处理 (不合格)
                                       → 返修处理 (不合格)
```

### 5.2 与采购的关联点

| 质检步骤 | 关联采购数据 | 说明 |
|---------|------------|------|
| 质检出库 | 采购入库单号 | 从哪个入库批次中抽检/全检 |
| 标签管理 | 物料编码、供应商 | 按供应商+物料生成配件ID |
| 质检结果 | 入库批次、供应商 | 不合格品追溯到供应商 |
| 退货处理 | 采购订单号、供应商 | 创建采购退货单，关联原订单 |

### 5.3 质检实际表结构（以数据库为准）

| 表名 | 中文说明 | 关键字段 | 备注 |
|------|---------|---------|------|
| `TQC10_RESULT` | 质检结果主表 | `qcbillid`, `outbillid`, `optyp`, `useflg` | `optyp=PJ/C1/C2` 配件/成品；关联出库单 |
| `TQC11_RESULTEID` | 质检结果明细（EID） | `qcbillid`, `eid`, `itemcd`, `itemtyp`, `qcstatus`, `inqty` | **实际唯一在用的质检明细表** |
| `TQC11_RESULTDT` | 质检结果明细（批次） | `qcbillid`, `itemcd`, `itemtyp`, `qcstatus` | `optyp=YH` 时写入，当前业务从未使用，数据为空 |

### 5.4 质检结果驱动的分支

```
质检结果 (TQC10/11)
    │
    ├── 合格 ──→ 质检入库 (TWH13, invtyp='3') → 进入可用库存
    │
    ├── 不合格-退货 ──→ 创建采购退货单 (TPC16/17) → 关联原订单 → 退货出库
    │
    ├── 不合格-返修 ──→ 创建返修工单 (ITSM) → 返修完成后重新质检
    │
    └── 不合格-换货 ──→ 创建换货流程（暂无此模块，可作为退货+新订单组合实现）
```

### 5.5 质检表需补字段

```sql
-- TQC11_RESULTEID 质检结果明细增加处理方式
ALTER TABLE tqc11_resulteid ADD COLUMN disposal VARCHAR(10);
-- disposal: 'accept'=合格入库 / 'return'=退货 / 'repair'=返修 / 'replace'=换货

-- 关联采购退货单（退货处理时写入）
ALTER TABLE tqc11_resulteid ADD COLUMN ref_return_id VARCHAR(8);
-- 退货单号，用于追溯"这个质检不合格项生成了哪张退货单"
```

## 六、销售预计划 → 采购需求自动关联

### 6.1 业务场景

销售预计划（`tms01_plancust`）确定客户需要的整机设备型号和数量后，系统按三级判断链路决定执行路径。

```
销售预计划（整机型号, 数量 N）
    │
    ├── 第一级：整机成品库存检查
    │   库存 ≥ N ──→ 直接生成销售订单
    │
    └── 第一级不满足
         │
         ├── 第二级：查 BOM（整机配件清单 tmm41/42）
         │   检查每个配件的库存
         │   │
         │   ├── 所有配件库存充足 ──→ 通知生产组装
         │   │        │
         │   │        └── 生产领料 → 组装 → 整机质检 → 成品入库
         │   │
         │   └── 部分配件库存不足 ──→ 第三级
         │
         └── 第三级：生成采购需求单
              缺什么配件 → 生成对应采购需求
              pctyp = '12' (订单采购)
              slbillid = 预计划号
              item_usage = 'sale'
              │
              ▼
           采购需求 → 采购订单 → 入库 → 质检 → 可用库存
              │
              └── 入库完成后，生产可领料组装
```

### 6.2 关联字段

| 表 | 字段 | 用途 |
|----|------|------|
| `tpc01_pcplan` | `slbillid` | 采购需求关联的销售预计划号 |
| `tpc01_pcplan` | `pctyp` | 采购类型，`'12'` = 订单采购（与销售单强关联） |
| `tpc02_pcplandt` | `item_usage` | 用途标记，`'sale'` = 销售备货，`'maintenance'` = 维护消耗品 |
| `tmm41_bom` | `bomcd` | 整机 BOM 主表，定义整机型号的配件清单 |
| `tmm42_bomdt` | `itemcd`, `bomqty` | BOM 明细，每台整机需要哪些配件及数量 |

### 6.3 三级判断逻辑详解

```
预计划：整机型号 M，需要 10 台

第一级 — 成品库存：
  SELECT SUM(qty) FROM TWH11 WHERE itemcd = 'M' AND whcd = '成品库'
  → 库存: 3 台 → 不满足，进入第二级

第二级 — BOM 配件库存：
  BOM: M = A×2 + B×1 + C×3
  需生产 7 台（= 10-3），需要配件: A×14, B×7, C×21

  检查库存:
  ├── A: 库存 20 ≥ 14 ✓
  ├── B: 库存 5 < 7 ✗ → 缺 2 个
  └── C: 库存 30 ≥ 21 ✓

  结论：B 配件不足，进入第三级

第三级 — 生成采购需求：
  PP001: slbillid=SL001, pctyp='12', item_usage='sale'
    明细: 配件B, 数量=2, 来源于预计划 SL001 的整机 M 生产缺口
```

### 6.4 采购完成后回调

```
采购需求 PP001 (slbillid=SL001) 全部入库完成
    │
    └── 更新预计划状态: "配件齐备，待生产"
        │
        └── 生产领料 → 组装 7 台 → 整机质检 → 入库成品库
            │
            └── 成品库存 = 3 + 7 = 10 → 预计划可执行
```

### 6.5 注意事项

- `pctyp='12'`（订单采购）必须关联 `slbillid`，创建需求时校验预计划是否存在
- 三级判断是逐级推进的：成品不够 → 看配件 → 配件不够 → 采购
- 同一预计划可能关联多个采购需求（多个配件缺货），通过 `slbillid` 聚合
- 采购执行看板应按 `slbillid` 分组展示"该预计划关联的所有采购需求进度"
- BOM 配方变更后，需重新计算配件缺口
- 预计划修改数量后，需重新执行三级判断

## 七、退货出库流程

### 6.1 当前状态

采购退货单审核通过后，目前没有生成出库单。需要仓库模块支持：

```
退货单审核通过 → 生成退货出库单 (TWH15, invtyp='7')
    → 仓库操作员确认出库 → 减少库存
    → 更新 TPC13.inqty（减少已入库量）
```

### 6.2 出库时需处理

| 操作 | 说明 |
|------|------|
| 生成出库单 | TWH15 关联退货单号 (refbillid = return_id) |
| 减少库存 | TWH11/12 库存明细更新 |
| 更新订单入库量 | TPC13.inqty -= 退货出库数量 |
| 更新退货状态 | TPC16 标记为已完成 |

## 八、跨模块数据一致性校验清单

### 7.1 数量校验

| 校验点 | 规则 |
|--------|------|
| 采购入库量 | `inqty ≤ rgsqty`（入库不超过订购） |
| 质检出库量 | `outqty ≤ inqty`（出库不超过入库） |
| 质检入库量 | `inqty ≤ 合格品数量` |
| 退货量 | `rpcqty ≤ inqty - 已退量` |
| 结算量 | `settle_qty ≤ 可结算余量` |

### 7.2 供应商追溯

```
需求 → 订单(供应商甲) → 入库(批次A) → 质检(批次A结果) → 退货(退给供应商甲)
  │                      │
  └── 订单(供应商乙) → 入库(批次B) → 质检(批次B结果)
```

关键：整个链路中 `suppliercd` 保持传递，不丢失。

### 7.3 状态同步

| 事件 | 更新 |
|------|------|
| 入库完成 | TPC13.inqty++, TPC20.linkstatus 更新 |
| 质检合格入库 | 库存增加 |
| 退货出库 | TPC13.inqty--, 库存减少 |
| 返修完成 | 重新进入质检流程 |

## 九、后续实施建议

### 阶段1：仓库退货出库（配合采购退货）
- 退货审核通过 → 自动生成出库单
- 出库确认 → 减少库存 + 更新订单 inqty

### 阶段2：仓库入库增强
- 入库时记录 `ref_rgstbillid` + `ref_rgstlineno`
- TWH14 冗余 `suppliercd`
- 入库后自动更新 TPC13.inqty

### 阶段3：质检模块
- 补 `disposal` 字段
- 不合格品 → 自动关联创建退货单
- 返修品 → 创建 ITSM 返修工单

### 阶段4：整机生产
- 生产出库 → 质检(整机标签) → 生产入库
- 整机组装完成后生成整机 EID

### 阶段5：全链路测试
- 按 PB 老系统 13 步完整流程走通
- 验证拆单/并单/多供应商场景的数据一致性
