# 销售管理（预计划）— 验收操作手册

> 对应技术文档：`销售管理_技术实现文档.md`

## 1. 验收前置条件

- **数据库**：plan_serve 表已创建（迁移 `d22e53c142d3`），plan_cust 已有 imple_billid 列
- **后端**：Flask 服务已启动，`/api/v1/sales/*` 端点可访问
- **前端**：Vue 前端已启动，预计划管理页面可访问
- **测试数据**：至少一个供应商、一个物料、一个仓库

---

## 2. 预计划创建验收

### 2.1 新建预计划（plantyp=00 新机开通）

**操作**：
1. 进入预计划管理 → 点击「新建预计划」
2. 填写：客户名称、磁卡号、客户编码；计划类型选「新机开通」；租赁/购买选「购买」；机型填测试编码；押金金额填 `3000`
3. 点击「保存」

**验证点**：
- [ ] 创建成功，列表中出现新记录，状态为「计划中」（00）
- [ ] 点击「详情」→ 呼出记录区域出现一条「待呼出」记录
- [ ] 客户表中出现对应记录，customer_status=「TEMP」

**API 验证**：
```bash
curl -X POST /api/v1/sales/plans \
  -H "Content-Type: application/json" \
  -d '{"plantyp":"00","custnm":"验收测试","custcd":"YS001","custcard":"YSK001","deposit":3000,"is_rent":"N"}'
# → 201, plan_status="00"
```

### 2.2 磁卡号重复检查

**操作**：使用相同的 custcard 再次创建预计划

**验证点**：
- [ ] 返回错误「磁卡号已被 XXX 使用」

## 3. 呼出确认验收

### 3.1 呼出单状态流转

**操作**：
1. 在详情抽屉中找到呼出记录
2. 通过 API 或后端将呼出单状态置为 `01`（已呼出）

**API 验证**：
```bash
# 查呼出单
curl /api/v1/sales/plans/<planno>/serve
# → dtlid

# 标记已呼出
curl -X POST /api/v1/sales/plan-serve/<dtlid>/transition \
  -H "Content-Type: application/json" \
  -d '{"to_status":"01"}'
```

**验证点**：
- [ ] 呼出单状态变为「已呼出」

### 3.2 呼出前置拦截

**操作**：呼出单未置为 01 时，直接调用实施确认

**验证点**：
- [ ] 返回错误「该预计划尚无已完成呼出的记录」

---

## 4. 状态流转验收

### 4.1 合法流转

| 从 | 到 | 预期 |
|----|----|------|
| 00 | 01 | ✅ 成功，客户 TEMP→PENDING |
| 01 | 02 | ✅ 成功（通过 implement 触发） |
| 02 | 04 | ✅ 成功（通过 complete 触发） |
| 任何 | 09 | ✅ 成功（通过 void 触发） |

### 4.2 非法流转

| 从 | 到 | 预期 |
|----|----|------|
| 00 | 04 | ❌ 拒绝 |
| 04 | 09 | ❌ 拒绝（终态） |

**API 验证**：
```bash
# 合法
curl -X POST /api/v1/sales/plans/<planno>/transition \
  -d '{"to_status":"01"}'  # → 200

# 非法
curl -X POST /api/v1/sales/plans/<planno>/transition \
  -d '{"to_status":"04"}'  # → 400
```

## 5. 实施确认验收（核心流程）

### 5.1 完整正向流程

**前置**：planno 的 plan_status=01 + 至少一条呼出单 status=01

**操作**：
```bash
curl -X POST /api/v1/sales/plans/<planno>/implement
```

**验证点**：
- [ ] 返回 200，downstream_id 非空
- [ ] plan_status 变为「02」（实施中）
- [ ] 查询预计划详情，imple_billid = downstream_id
- [ ] 下游 ITSM 单据真实存在（查询 `/itsm/maintenance-open/<id>` 返回 200）
- [ ] 若押金>0，tmm61_deposit_dtl 新增一条记录（c_type=预计划押金）

### 5.2 各 plantyp 下游单据验证

| plantyp | 验证端点 |
|---------|---------|
| 00 | `GET /itsm/maintenance-open/<id>` |
| 10 | `GET /itsm/device-change/<id>` |
| 20 | `GET /itsm/maintenance-renovate/<id>` |
| 30 | `GET /itsm/recycle-task/<id>` |
| 40 | `GET /itsm/store-close/<id>` |

### 5.3 幂等检查

**操作**：对同一 planno 再次调用 implement

**验证点**：
- [ ] 返回错误「下游单据已生成，不可重复实施」

## 6. 销售出库验收

### 6.1 生成 OV=1 出库草稿

**前置**：plan_status=02

**操作**：
```bash
curl -X POST /api/v1/sales/plans/<planno>/outbound \
  -H "Content-Type: application/json" \
  -d '{"whcd":"04"}'
```

**验证点**：
- [ ] 返回 201，outbillid 非空
- [ ] 查询出库单详情，invtyp=1, refbillid=planno
- [ ] plan_cust.is_outflag='1'
- [ ] 重复调用 → 返回「已存在出库单」

## 7. 完成验收

### 7.1 完成预计划

**前置**：plan_status=02

**操作**：
```bash
curl -X POST /api/v1/sales/plans/<planno>/complete
```

**验证点**：
- [ ] plan_status 变为「04」（已完成）
- [ ] 客户 customer_status 变为「ACTIVE」

### 7.2 状态前置校验

**操作**：对 plan_status=00 的预计划调用 complete

**验证点**：
- [ ] 返回 400「需要 02（实施中）才能完成」

---

## 8. 作废验收

### 8.1 作废草稿预计划

**前置**：plan_status=00/01/02

**操作**：
```bash
curl -X POST /api/v1/sales/plans/<planno>/void \
  -H "Content-Type: application/json" \
  -d '{"remark":"测试作废"}'
```

**验证点**：
- [ ] plan_status 变为「09」（已作废）
- [ ] 客户 customer_status 变为「INVALID」

### 8.2 已完成不可作废

**操作**：对 plan_status=04 的预计划调用 void

**验证点**：
- [ ] 返回 400「已完成的预计划不可作废」

## 9. 客户生命周期验收

### 9.1 完整生命周期追踪

```
创建预计划 → customer_status=TEMP
  ↓ (transition 00→01)
customer_status=PENDING
  ↓ (complete)
customer_status=ACTIVE
```

或：
```
创建预计划 → customer_status=TEMP
  ↓ (void)
customer_status=INVALID
```

**验证 SQL**：
```sql
SELECT cust_cd, cust_nm, customer_status, preplan_id
FROM tmm22_customers WHERE preplan_id = '<planno>';
```

## 10. 数据一致性验收

### 10.1 预计划-呼出单关联
```sql
SELECT p.planno, p.plan_status, s.status AS serve_status
FROM plan_cust p LEFT JOIN plan_serve s ON p.planno = s.planno
WHERE p.planno = '<planno>';
```

### 10.2 预计划-下游单据关联
```sql
SELECT planno, plantyp, plan_status, imple_billid
FROM plan_cust WHERE planno = '<planno>';
-- imple_billid 应指向对应的 ITSM 单据
```

### 10.3 押金明细
```sql
SELECT * FROM tmm61_deposit_dtl WHERE r_billid = '<planno>';
```
