# 预计划机型联动与采购触发技术方案

> 承接 `预计划表单与机型联动优化方案.md` §3.2/§3.3 和 `采购-仓库-质检跨模块流程衔接设计.md` §7，
> 解决预计划表单机型选择后的库存显示、押金联动、BOM 展开与采购需求自动触发。

## 一、问题清单与根因

| # | 问题 | 根因 | 影响 |
|---|------|------|------|
| 1 | 旧机翻新(pos_from=00 商用仓库)不显示计划机型+库存 | `showModelPicker` 计算属性已涵盖 plantyp=20/30/40,但模板 `v-if="showModelPicker && isPosFrom('00')"` 多余限制 pos_from='00',导致 30/40 无 pos_from 时机型选择器不显示 | 30/40 机型选择器不显示 |
| 2 | 非商用仓库时押金未按源机型关联字典价格 | `onModelSelect` 只在机型下拉 change 时带价,旧设备块无联动 | 20/30/40 选门店移机/烟草直调时押金为 0 |
| 3 | DepositPosModel 与 BOM/Item 价格数据冗余 | `tmm61_deposit_posmodel` 独立维护机型押金/售价,与 `tip01_price`(物料价格中心)和 `tmm41_bom`(在产状态)职责重叠 | 机型众多时多处维护,易不一致 |
| 4 | 前端库存查询 API 路径错误 | `onModelSelect` 调 `/warehouse/stock`(不存在),实际是 `/reports/inventory/snapshot` | 库存永远为 0 |
| 5 | 库存不足未触发采购需求 | 后端无 BOM 展开+齐套计算+采购需求生成服务 | §7.2 链路断裂 |

## 二、总体设计

### 2.1 机型→物料→BOM→库存 的关联链路(对齐 PB 语义)

```
tmm12_items (物料主表)
  ├── item_cd       物料编码(成品/配件/耗材) — 即机型编码
  ├── item_nm       物料名称
  ├── typflg        物料类型('1'=成品)
  └── useflg        物料有效性

tmm41_bom / tmm42_bomdt (BOM 配方)
  ├── bomcd = item_cd(成品编码即 BOM 编码)
  ├── useflg        '1'=在产可选 / '0'=停产(PB 语义:配方有效即机型在产)
  └── details.itemcd / bomqty  配件编码 / 单台用量

tip01_price (价格中心)
  ├── (itemcd, busityp) 联合主键
  ├── busityp='10'  销售价
  ├── busityp='20'  采购价
  ├── busityp='30'  维护品价格
  ├── busityp='40'  押金(新增)
  └── itemprice     单价

twh11_detail (库存明细)
  ├── itemcd        物料编码
  ├── whcd          仓库编码
  └── itemqty       库存数量
```

**PB 语义对齐**: PB 源码中 `tmm41_bom.useflg='1'` 同时承担"配方有效"和"机型在产可选"两个职责
(见 `w_wh_scout_pop.srw:638`、`w_r_sl_audit_direct.srw:246`、`w_r_mm_label_zjpj.srw:63`),
不新增 `is_production` 字段,复用 `Bom.useflg` 作为在产机型筛选条件。

### 2.2 预计划机型选择联动流程

```
用户选机型(item_cd)
  │
  ├── 1. 查在产机型接口 GET /items/pos-models
  │       → Item JOIN Bom WHERE typflg='1' AND b.useflg='1'
  │       → 带 rent_money(busityp=40)/sale_money(busityp=10) → 写 form.deposit
  │
  ├── 2. 查 twh11_detail 汇总库存 → 显示 stockQty
  │       API: GET /reports/inventory/snapshot?itemcd=<item_cd>&per_page=200
  │
  └── 3. 库存 > 0 → 可保存,等待实施时分配 posid
      库存 = 0 → 提示"库存不足,将触发采购需求"
                  │
                  └── 保存预计划时调用 BOM 展开服务
                      ├── 配件齐套 → 提示"可生产,请下达生产工单"
                      └── 配件不足 → 自动生成采购需求(tpc01_pcplan)
                                      slbillid = planno
                                      pctyp = '12'
                                      item_usage = 'sale'
```

### 2.3 非商用仓库(pos_from=01/02/03/04)的押金联动

```
用户选旧设备ID(门店移机/翻新场景)
  │
  ├── 旧设备块: 选 posid → 自动带出 pos_item(旧机型编码=item_cd)
  │
  └── 查在产机型列表 WHERE item_cd = pos_item
      ├── 找到 → form.deposit = rent_money(busityp=40)
      └── 未找到 → form.deposit = 0,提示"该机型未配置押金或已停产"
```

## 四、后端实现

### 4.1 新增 `PlanStockService` — 库存校验与采购触发

**文件**: `app/services/sales_service.py` 新增类(或独立文件 `app/services/plan_stock_service.py`)。

```python
class PlanStockService:
    """预计划库存校验与采购需求触发。"""

    @staticmethod
    def check_stock(model_cd: str) -> dict[str, Any]:
        """查询机型对应成品的库存汇总。

        Args:
            model_cd: 机型编码(即 item_cd,直接作为物料编码查询)
        Returns:
            {model_cd, item_cd, total_qty, wh_details: [{whcd, whnm, qty}]}
        """
        # model_cd 即 item_cd,无需桥接
        # 1. 查 twh11_detail WHERE itemcd=model_cd GROUP BY whcd
        # 2. 汇总返回

    @staticmethod
    def expand_bom_and_check(model_cd: str, qty: int = 1) -> dict[str, Any]:
        """BOM 展开并校验配件齐套。

        Args:
            model_cd: 机型编码(即 item_cd)
            qty: 需求数量(默认 1 台)
        Returns:
            {model_cd, item_cd, qty, lines: [{itemcd, item_nm, need_qty, stock_qty, enough}], all_enough}
        """
        # 1. model_cd 即 item_cd,直接调 BomService.expand(model_cd, qty)
        # 2. 对每个配件查 twh11_detail 库存
        # 3. 判断 need_qty <= stock_qty → enough

    @staticmethod
    def trigger_procurement(planno: str, model_cd: str, qty: int = 1) -> dict[str, Any]:
        """库存不足时触发采购需求。

        Args:
            planno: 预计划单号(作为 slbillid)
            model_cd: 机型编码
            qty: 需求数量
        Returns:
            {pcplanid, created_lines: [{itemcd, item_nm, need_qty}]}
        """
        # 1. expand_bom_and_check(model_cd, qty)
        # 2. 筛选 enough=False 的配件
        # 3. 调 PurchasePlanService.create(
        #      data={pctyp:'12', slbillid:planno, ...},
        #      details=[{itemcd, need_qty, item_usage:'sale'}, ...],
        #      creator=opercd
        #    )
        # 4. 返回采购需求单号
```

```python
@sales_bp.get("/plans/stock-check")
@login_required
def check_plan_stock():
    """预计划机型库存校验。
    Query: model_cd=xxx
    Returns: {total_qty, wh_details}
    """
    model_cd = request.args.get("model_cd", "").strip()
    if not model_cd:
        return error_response("model_cd 不能为空", 400)
    data = PlanStockService.check_stock(model_cd)
    return success_response(data=data)

@sales_bp.get("/plans/bom-check")
@login_required
def check_plan_bom():
    """预计划机型 BOM 齐套校验。
    Query: model_cd=xxx&qty=1
    Returns: {lines, all_enough}
    """
    model_cd = request.args.get("model_cd", "").strip()
    qty = int(request.args.get("qty", "1"))
    data = PlanStockService.expand_bom_and_check(model_cd, qty)
    return success_response(data=data)
```

### 4.3 预计划保存时自动触发采购

**文件**: `app/services/sales_service.py` `PlanCustService` 新增私有方法 `_try_trigger_procurement`,`create` 和 `update` 末尾均调用:

```python
@staticmethod
def _try_trigger_procurement(record, data, operator):
    """库存不足自动触发采购需求(仅 pos_from=00 商用仓库,不限 plantyp)。

    供 create() 和 update() 共用。条件放宽为不限 plantyp,
    翻新(20)/关门(40)等选商用仓库时同样需要采购备货。
    """
    pos_from = (data.get("pos_from") or getattr(record, "pos_from", "") or "").strip()
    pos_item = (data.get("pos_item") or getattr(record, "pos_item", "") or "").strip()
    if pos_from != "00" or not pos_item:
        return
    # ... check_stock + trigger_procurement
```

**触发时机**:
- `create()`: 首次保存且 pos_from=00 + pos_item 已选时触发
- `update()`: 先保存草稿、后续才选机型场景补触发(避免遗漏)
- 重复触发防护: `trigger_procurement` 内部检查 `slbillid=planno` 已存在则跳过

## 五、前端实现

### 5.1 修正 `showModelPicker` 可见性(问题 1)

> 变量名由 `showPropoItem` 改为 `showModelPicker`,语义更准确(PB 原意"推荐物料"在新系统中承载"机型选择"职责)。

**文件**: `frontend/src/views/sales/PlanList.vue:423`

```typescript
const showModelPicker = computed(() => {
  // 计划机型行(选机型+查库存):
  //   00(00仓库) 全新开通选机型
  //   20(00仓库) 旧机翻新选目标机型
  //   30/40 取回/关门选机型(无 pos_from,直接显示)
  if (form.plantyp === '00' && isPosFrom('00')) return true
  if (form.plantyp === '20' && isPosFrom('00')) return true
  if (['30', '40'].includes(form.plantyp)) return true
  return false
})
```

**根因澄清**: 模板 `v-if="showModelPicker && isPosFrom('00')"` 本身不限 plantyp,限制来自计算属性定义。原 `showPropoItem` 定义为 `plantyp==='00' && isPosFrom('00')`,导致 plantyp=20 时返回 false。

### 5.2 修正库存查询 API 路径与响应字段(问题 4)

**文件**: `frontend/src/views/sales/PlanList.vue:476-486`

**响应字段确认**: `/reports/inventory/snapshot` 返回 `{items: [{whcd, warehouse_name, itemtyp, itemcd, itemqty, updated_at}], total}`,字段名 `itemqty`(int),前端用 `x.itemqty` 汇总。

```typescript
async function onModelSelect(val: string) {
  const m = modelOptions.value.find(x => x.model_cd === val)
  if (m) form.deposit = m.rent_money || 0
  if (!val) { stockQty.value = 0; return }
  try {
    const r = await request.get('/reports/inventory/snapshot', {
      params: { itemcd: m?.item_cd || val, per_page: 200 }
    }) as any
    const items = r?.data?.items || []
    stockQty.value = items.reduce((s: number, x: any) => s + (Number(x.itemqty) || 0), 0)
    if (stockQty.value <= 0) {
      ElMessage.warning('该机型库存不足,保存后将自动触发采购需求')
    }
  } catch { stockQty.value = 0 }
}
```

## 七、风险与注意事项

### 7.1 BOM 展开依赖 item_cd 正确映射

`pos_item`(机型编码)即 `tmm12_items.item_cd`,直接作为 BOM 编码查询。若该 item_cd 在 `tmm41_bom` 中无记录或 `useflg=0`,`expand_bom_and_check` 返回空 lines,需提示"该机型未配置 BOM 或已停产"。

### 7.2 采购需求生成需 operator

- `create()` 时 operator=creator(登录用户)
- `update()` 时 operator=g.current_user(API 层传入)
- 预计划创建者 `opercd` 作为采购需求 `creator`,需确保登录用户有采购模块权限
- `update()` 方法签名已加 `operator` 参数,API 层 `update_plan` 传 `g.current_user`

### 7.3 其他注意事项

1. **重复触发防护**: 同一预计划多次保存时,`trigger_procurement` 内部检查 `tpc01_pcplan.slbillid=planno` 是否已存在,避免重复生成。
2. **BOM 变更不自动重算**: 按 §7.5 注意事项,BOM 变更后不自动重算已生成采购需求,需人工处理。
3. **生产工单触发暂不实现**: 本方案只到"生成采购需求",`配件充足 → 生产工单` 链路待 MES 模块完善后补充。
4. **DepositPosModel 历史数据**: 5 条机型级数据(单屏/双屏/4Q/7Q/海晟)已按 BOM 前缀展开迁移至 tip01_price busityp=40,原表保留不删除。
