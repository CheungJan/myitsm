# 预计划表单与机型联动优化方案

> 基于 PB 源码（`new_deposit.pbl/w_plan_cust_befor_new.srw`）逐行还原 +
> 跨模块衔接设计文档（`采购-仓库-质检跨模块流程衔接设计.md` §7）的完整方案。

## 一、问题总览

| # | 问题 | 现状 | 影响 |
|---|------|------|------|
| 1 | 新建预计划缺少 `cust_useflg` 门店无效勾选 | 后端有字段+逻辑，前端无录入 | complete() 联动无法触发 |
| 2 | BOM/机型在产停产无字段，机型手工填写 | 无下拉、无联动、无库存显示 | 操作员盲填，无法选型 |
| 3 | 机型押金标准用哪张表 | `tmm61_deposit_posmodel` 已有但无前端 | 选中机型后押金售价未自动带入 |

### 2.3 pos_from 二级控制（plantyp=00/20 时生效）

| pos_from | 含义 | 显隐规则 |
|----------|------|---------|
| `00` | 建议机型（全新安装） | **隐藏** pos_item / posid / solve_type / new_xxx / cust_useflg |
| `01` | 移机（从其他门店） | **显示** 全部字段 |
| `02` | 返修重开 | **显示** 全部字段 |

### 2.4 cust_useflg 在各 plantyp 的语义

| plantyp | 勾选语义 | 后端联动（`_apply_cust_useflg_invalidation`） |
|---------|---------|------|
| 00 | 移机时勾选 → 源门店失效 | `new_custcd` → `useflg='0'` |
| 20 | 移机时勾选 → 源门店失效 | 同上 |
| 30 | 取机勾选 → 本门店失效 | `custcd` → `useflg='0'` |
| 10 | 不显示（无条件失效） | 源门店自动 `useflg='0'` |
| 40 | 不显示（走 s_status） | `set_store_close_status` |

## 三、机型与库存联动分析

### 3.1 现状

| 层次 | 现状 |
|------|------|
| BOM `useflg` | BomList.vue 编辑弹窗有下拉，列表不显示；语义是"配方有效"，非"机型在产" |
| Item 在产停产 | **无此字段**。`typflg`/`purchasetyp`/`consume` 均非此语义 |
| `tmm61_deposit_posmodel` | 模型 + API 已有（CRUD），**前端无维护页面** |
| 预计划机型选择 | PlanList.vue:162 是 `<el-input>` 手工填写 |

### 3.2 设计文档 §7.2 规划的链路

```
plan_cust (planno, pos_item)
  ├── 检查成品库存 → 有库存：直接分配 posid
  └── 无库存 → BOM展开 → 配件不足 → 采购需求 → 入库 → 生产 → 质检
```

**当前后端未实现成品库存校验和采购触发逻辑。**

### 3.3 表的职责边界

```
tmm12_items          物料主表（配件+整机+耗材）
tmm61_deposit_posmodel  机型押金标准表（每机型一行）← 本次使用
tmm41_bom / tmm42_bomdt  BOM配方表
twh11_detail          库存明细表
```

**结论**：`DepositPosModel.useflg` 作为"机型在产/停产"标志。因为：
- 该表就是机型维度主数据，`useflg=1` 在产 / `useflg=0` 停产
- 不宜在 Item 表加在产字段——物品可能有效但机型已停产
- 不宜在 BOM 表加——BOM 有效代表配方在用，非机型停产
- 不宜用字典(YJ)——押金标准是实体数据带金额，字典不适合

## 四、实施方案（确认后执行）

### 第 1 步：补预计划表单字段

**文件**：`frontend/src/views/sales/PlanList.vue`

| 新增字段 | 显示条件 | 说明 |
|---------|---------|------|
| `pos_from` 设备来源 | plantyp=00/10/20 | 下拉：00建议机型 / 01移机 / 02返修 |
| `cust_useflg` 门店无效 | (plantyp=00/20 且 pos_from='01/02') 或 plantyp=30 | 勾选框 |
| `new_custcard` 新磁卡号 | plantyp=00(pos_from=01/02) 或 plantyp=10 | 输入框 |
| `new_positem` 新机型 | plantyp=00(pos_from=01/02) 或 plantyp=10 | 输入框 |
| `new_posid` 新设备ID | plantyp=00(pos_from=01/02) 或 plantyp=10 | 输入框 |
| `new_custnm` 新客户名 | plantyp=00(pos_from=01/02) 或 plantyp=10 | 输入框 |
| `new_address` 新地址 | plantyp=00(pos_from=01/02) 或 plantyp=10 | 输入框 |
| `new_phoneno` 新电话 | plantyp=00(pos_from=01/02) 或 plantyp=10 | 输入框 |

**需扩展 Schema**：`PlanCustCreate` 当前只有 13 个字段（plantyp/custcd/custnm/custcard/custrnm/busityp/address/contactor/phoneno/pos_item/is_rent/deposit/yun_type）。API 入口用 `model_validate()` → `model_dump(exclude_none=True)`，Pydantic 会静默丢弃 schema 外字段。需补：cust_useflg / pos_from / new_custcard / new_positem / new_posid / new_custnm / new_address / new_phoneno / propo_item / solve_type / classcd / pptcode / is_contract / commmode / custnew / upload_type。

### 第 2 步：机型押金标准维护页

**新建文件**：`frontend/src/views/sales/PosModelList.vue`

| 功能 | 说明 |
|------|------|
| 列表 | 查询 `GET /api/v1/deposit/pos-models` |
| 新增/编辑 | `POST/PUT /api/v1/deposit/pos-models` |
| 字段 | model_cd(机型编码) / model_nm(机型名称) / rent_money(租金) / sale_money(售价) / useflg(有效标志) |

**可选**：`tmm61_deposit_posmodel` 加 `item_cd` 字段关联 `tmm12_items`，机型下拉可通过物料体系联动。

**菜单**：挂到"基础数据"下，新增 `pos-models` 菜单项。

### 第 3 步：预计划机型选择联动

| 改动 | 文件 | 内容 |
|------|------|------|
| 机型字段改为下拉 | PlanList.vue | `<el-select>` 替代 `<el-input>`，选项来自 `DepositPosModel` (useflg='1') |
| 押金自动带入 | PlanList.vue | 选中机型 → `form.deposit = selected.rent_money` |
| 库存量显示 | 新增 API | 或复用现有库存查询，显示选中机型的成品库存量 |

**延期**：库存不足自动触发采购需求（涉及采购模块、BOM 展开、齐套计算，单独立项）。
