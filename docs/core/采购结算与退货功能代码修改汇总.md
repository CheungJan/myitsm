# 采购结算与退货功能代码修改汇总

## 1. 文档目的

本文汇总本次采购结算单（TPC14/TPC14_DT）与采购退货单（TPC16/TPC17）功能开发后的代码变更、实现范围、关键业务规则、审核发现与验证结果，作为后续联调、测试补齐、代码评审和上线前检查依据。

## 2. 修改范围

本次功能主要覆盖后端采购模块的 Schema、Repository、Service、API 四层，并为前端 API 与页面实现提供接口基础。

| 层级 | 文件 | 变更说明 |
|---|---|---|
| Schema | `app/schemas/procurement.py` | 增加采购结算与退货的创建、编辑、明细 Schema，支持嵌套明细校验 |
| Repository | `app/repositories/procurement_repository.py` | 扩展结算单与退货单数据访问能力，增加明细操作、累计数量查询、筛选查询 |
| Service | `app/services/procurement_service.py` | 重写采购结算与采购退货服务，补齐 CRUD、审核、作废、数量校验与可操作明细查询 |
| API | `app/api/procurement.py` | 补齐结算与退货完整 REST 接口，包括列表、详情、创建、编辑、审核、作废、可结算/可退货查询 |
| 前端 API | `frontend/src/api/procurement.ts` | 计划配套增加结算/退货接口类型与调用函数 |
| 前端页面 | `frontend/src/views/procurement/PurchaseBillList.vue`、`frontend/src/views/procurement/ReturnPurchaseList.vue` | 计划配套实现结算与退货列表、新建、审核、作废交互 |

## 3. 采购结算功能实现说明

### 3.1 数据结构与请求契约

`PurchaseBillCreate` 支持以下核心字段：

- `suppliercd`：供应商编码。
- `pay_type`：付款方式，支持 `COD`、`PIA`、`DEP`、`MON`、`INS`。
- `invoice_no` / `invoice_date`：供应商发票信息。
- `pcdate`：结算日期。
- `whcd`：入库仓库。
- `details`：结算明细，至少一行。

`PurchaseBillDetailCreate` 明细字段包括：

- `ref_rgstbillid`：来源采购订单号。
- `ref_rgstlineno`：来源订单行号。
- `itemcd`：物料编码。
- `settle_qty`：本次结算数量。
- `settle_price`：结算单价。

### 3.2 Repository 层能力

`PurchaseBillRepository` 已扩展：

- `list_by_filters()`：支持供应商、审核状态、付款方式、日期范围分页筛选，并默认排除作废单据。
- `create()`：使用 `_gen_master_id("SB", "采购结算单号")` 生成结算单号。
- `update()`：排除单号、明细、制单人、制单时间、审核字段等不可直接更新字段。
- `add_detail()`：写入 `TPC14_DT` 结算明细。
- `clear_details()`：编辑时全量替换结算明细。
- `list_details()`：按行号返回结算明细。
- `get_settled_total()`：统计订单行已结算数量，支持排除当前结算单，避免编辑时重复计算自身数量。

### 3.3 Service 层业务规则

`PurchaseBillService` 已实现：

- `get()`：返回主表并附带 `details` 明细。
- `list_records()`：分页查询结算单列表。
- `create()`：创建结算单并写入明细。
- `update()`：编辑未审核结算单，支持明细全量替换。
- `audit()`：审核结算单。
- `void()`：作废结算单。
- `get_settleable_items()`：查询订单可结算商品行。

结算数量规则：

| 付款方式 | 可结算数量口径 |
|---|---|
| `COD` 货到付款 | 已入库数量 - 已结算数量 |
| `MON` 月结 | 已入库数量 - 已结算数量 |
| `PIA` 款到发货 | 订购数量 - 已结算数量 |
| `DEP` 预付+尾款 | 订购数量 - 已结算数量 |
| `INS` 分期付款 | 订购数量 - 已结算数量 |

关键校验：

- 来源订单行必须存在。
- 本次结算数量不能超过可结算余量。
- 创建或编辑时自动计算 `settle_amt` 与 `total_settle_amt`。
- 作废时同时设置 `useflg = "9"` 与 `auditflg = "9"`。

## 4. 采购退货功能实现说明

### 4.1 数据结构与请求契约

`ReturnPurchaseBillCreate` 支持以下核心字段：

- `ref_rgstbillid`：来源采购订单号。
- `return_reason`：退货原因。
- `pcdate`：退货日期。
- `whcd`：仓库编码。
- `memo`：备注。
- `details`：退货明细，至少一行。

`ReturnPurchaseBillDetailCreate` 明细字段包括：

- `itemcd`：物料编码。
- `ref_rgstlineno`：来源订单行号。
- `rpcqty`：退货数量。
- `return_price`：退货单价。
- `eid` / `seid`：设备与序列信息。
- `units`：单位。
- `line_reason`：行级退货原因。

### 4.2 Repository 层能力

`ReturnPurchaseRepository` 已扩展：

- `list_by_filters()`：支持供应商、审核状态、日期范围分页筛选，并默认排除作废单据。
- `create()`：使用 `_gen_master_id("RT", "采购退货单号")` 生成退货单号。
- `update()`：更新退货单主表可编辑字段。
- `add_detail()`：写入退货明细。
- `clear_details()`：编辑时全量替换退货明细。
- `list_details()`：按行号返回退货明细。
- `get_returned_total()`：统计订单行已退货数量。

### 4.3 Service 层业务规则

`ReturnPurchaseService` 已实现：

- `get()`：返回主表并附带 `details` 明细。
- `list_records()`：分页查询退货列表。
- `create()`：创建退货单并写入明细。
- `update()`：编辑未审核退货单，支持明细全量替换。
- `audit()`：审核退货单。
- `void()`：作废退货单。
- `get_returnable_items()`：查询订单可退货商品行。

退货数量规则：

- 来源订单行必须存在。
- 来源订单行必须已有入库数量。
- 可退数量 = 已入库数量 - 已退货数量。
- 本次退货数量不能超过可退余量。
- 创建或编辑时自动计算 `return_amt` 与 `pcamt`。
- 作废时同时设置 `useflg = "9"` 与 `auditflg = "9"`。

## 6. 本次代码审核修复项

本次审核后已修复以下问题：

1. `get_settleable_items()` 与 `get_returnable_items()` 中循环变量原使用 `dt`，会遮蔽模块级 `datetime as dt` 别名。已统一改为 `detail_line`。
2. `create_settlement()` 与 `create_return()` 原未捕获 Service 层数量校验抛出的 `ValueError`，可能导致 500。已增加 `try/except ValueError` 并统一返回 400。

### 7.3 测试现状

执行现有采购测试时发现失败项，但失败原因主要是历史测试仍引用旧路由：

- `/api/v1/procurement/plans`
- `/api/v1/procurement/registers`
- `/api/v1/procurement/bills`

当前实际路由已使用：

- `/api/v1/procurement/requisitions`
- `/api/v1/procurement/orders`
- `/api/v1/procurement/settlements`

因此现有测试失败不应直接归因为本次结算/退货功能实现，后续需要单独更新测试用例契约。

## 8. 风险与待办

| 项目 | 风险 | 建议 |
|---|---|---|
| 数据库迁移 | 若迁移未执行，新增字段和 `TPC14_DT` 明细表不可用 | 按计划执行 Alembic 迁移并验证约束 |
| ORM 模型 | 若模型未与迁移同步，运行时可能出现字段缺失 | 检查 `PurchaseBillDt`、`ReturnPurchaseBillDt`、主表新增字段 |
| 旧测试 | 测试路由仍为历史命名 | 单独更新 `tests/test_procurement_api.py` |
| 并发创建 | 累计结算/退货数量存在并发超量风险 | 后续可增加数据库事务锁或唯一业务校验 |
| 作废单编辑 | 当前部分逻辑允许 `auditflg = "9"` 的记录进入编辑判断 | 建议最终统一为仅 `auditflg = "0"` 且 `useflg != "9"` 可编辑 |
| 审核防御 | `audit()` 主要依赖 `auditflg` 拦截作废单 | 可补充 `useflg == "9"` 防御判断 |

## 9. 后续建议

1. 补齐并执行 Alembic 数据库迁移。
2. 校验 ORM 模型与数据库结构完全一致。
3. 更新采购模块测试用例，覆盖新路由与新请求体。
4. 增加结算/退货创建、编辑、审核、作废的集成测试。
5. 前端联调时重点验证付款方式影响可结算数量的逻辑。
