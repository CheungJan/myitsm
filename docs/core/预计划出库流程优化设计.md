# 预计划出库流程优化设计

## 1. 背景

预计划实施环节涉及"制定计划 → 实施确认 → 出库 → 下游单据完成 → 预计划完成"的业务链路。当前实现存在以下问题：

1. **`is_outflag` 语义错位**：`create_outbound()` 在创建 OV=1 出库草稿时立即置 `is_outflag='1'`，但业务期望"出库单审核完成后"才标志为已出库。
2. **出库判定维度缺失**：`implement()` 自动出库与 `create_outbound()` 手动出库仅判断 `posid` 是否存在，未按设备来源 `pos_from` 区分是否需要我方出库。
3. **非商用仓库来源无出库概念**：门店移机、烟草直调、IT公司、海晟公司等来源不需要我方出库单，但当前仍可能触发出库逻辑。
4. **出库入口归属错位**：出库按钮在"预计划管理"页面，但出库属于"实施"环节，应归属"计划实施管理"模块。
5. **无批量出库能力**：批量开通场景需逐单出库，操作繁琐。

## 2. 核心判定规则

### 2.1 出库必要性判定

```
需要我方出库 ⟺ pos_from == '00'（商用仓库）
```

所有出库相关行为（自动出库、手动按钮、批量选择、`is_outflag`）统一受此约束。

### 2.2 设备来源字典（pos_from）

| pos_from | 来源 | 是否我方出库 | 说明 |
|----------|------|------------|------|
| **00** | **商用仓库** | ✅ **需要 OV=1 出库单** | 设备从我方仓库发出 |
| 01 | 门店移机 | ❌ 不需要 | 设备在门店间流转，非我方仓库 |
| 02 | 烟草直调 | ❌ 不需要 | 第三方直调 |
| 03 | IT公司 | ❌ 不需要 | 外部来源 |
| 04 | 海晟公司 | ❌ 不需要 | 外部来源（含翻新仓库） |

### 2.3 各计划类型的出库适用性

| plantyp | 类型 | 出库判定 | 依据 |
|---------|------|---------|------|
| 00 | 新机开通 | 视 pos_from | 商用仓库来源→出库 |
| 10 | 磁卡号变更 | ❌ 永不出库 | 仅改磁卡号，不涉及设备出库 |
| 20 | 旧机翻新 | 视 pos_from | 新机来自商用仓库→出库；来自翻新仓库/别门店→不出库 |
| 30 | 取机回收 | ❌ 不出库 | 收回是入库方向（资产回收链路） |
| 40 | 门店关闭 | ❌ 不出库 | 收回是入库方向（同上） |

**统一公式**：`需要出库 = (pos_from == '00')`（10/30/40 业务上不会选商用仓库作为出货源）

## 3. is_outflag 三态语义

### 3.1 状态定义

| 值 | 含义 | 触发点 |
|----|------|--------|
| `'N/A'` | 不适用（非商用仓库来源） | 创建/更新时 `pos_from != '00'` |
| `'0'` | 待出库 | 商用仓库来源创建时；出库单反审核回退 |
| `'1'` | 已出库 | OV=1 出库单**审核通过后**回写 |

### 3.2 状态流转

```
创建预计划（pos_from='00'）→ is_outflag='0'
创建预计划（pos_from!='00'）→ is_outflag='N/A'
        │
        │  生成 OV=1 出库草稿（create_outbound）
        │  is_outflag 保持 '0'（草稿未审核）
        ▼
OV=1 出库单审核通过（StockOutService.audit）
        │
        │  回写 is_outflag='1'
        ▼
is_outflag='1'（已出库）
        │
        │  反审核（StockOutService.unaudit）
        │  回退 is_outflag='0'
        ▼
is_outflag='0'（待出库）
```

### 3.3 列宽调整

原 `is_outflag VARCHAR(2)` 无法容纳 `'N/A'`（3字符），拓宽为 `VARCHAR(4)`。

## 5. 后端改动

### 5.1 已完成（P0）

#### `app/services/sales_service.py`

**`create()`**：按 `pos_from` 初始化 `is_outflag` 三态
```python
_pos_from_init = (model_data.get("pos_from") or "").strip()
model_data["is_outflag"] = "0" if _pos_from_init == "00" else "N/A"
```

**`update()`**：`pos_from` 变更时重算，已出库(`'1'`)不覆盖
```python
if "pos_from" in data and (record.is_outflag or "") != "1":
    _pos_from_upd = (data.get("pos_from") or "").strip()
    data["is_outflag"] = "0" if _pos_from_upd == "00" else "N/A"
```

**`create_outbound()`**：删除草稿创建即置 `'1'`，改为审核后回写
```python
# 注：is_outflag 不在此置 '1'。草稿创建阶段仍为 '0'（待出库），
# 待 OV=1 出库单审核通过后由 StockOutService.audit 回写 '1'（已出库）。
```

#### `app/services/warehouse_service.py`

**`StockOutService.audit()` OV=1 分支**：审核通过后回写关联预计划 `is_outflag='1'`
```python
if record.refbillid:
    from app.models.sales import PlanCust as _PlanCust
    db.session.query(_PlanCust).filter(
        _PlanCust.planno == record.refbillid,
        _PlanCust.is_outflag != "N/A",
    ).update({"is_outflag": "1"}, synchronize_session=False)
```

**`StockOutService.unaudit()` OV=1 分支**：反审核回退 `is_outflag` 从 `'1'` 到 `'0'`
```python
if record.refbillid:
    from app.models.sales import PlanCust as _PlanCust
    db.session.query(_PlanCust).filter(
        _PlanCust.planno == record.refbillid,
        _PlanCust.is_outflag == "1",
    ).update({"is_outflag": "0"}, synchronize_session=False)
```

## 9. 验证要点

### 9.1 P0 验证

1. 创建 `pos_from='00'` 预计划 → `is_outflag='0'`
2. 创建 `pos_from='01'` 预计划 → `is_outflag='N/A'`

## 10. 行业主流做法参考

### 10.1 预留-拣货-发货三段式

```
订单确认 → 库存预留(reservation) → 拣货(picking) → 发货过账(goods issue)
```
- 方案A"预选 EID" = 库存预留（当前代码 `reserve_planno` 已实现）
- 出库单审核 = 发货过账，此时才置"已发货"标志

### 10.2 波次拣货 / 合并发货

- 批量出库 = 行业的**波次出库**：将多个订单合并到一个拣货波次/发货单
- SAP：交货单(Delivery)可合并多个销售订单行；WMS：波次(Wave)聚合多个出库任务
- 关键：**订单与发货单是多对多**，通过中间关联表或明细行记来源单号

### 10.3 标志位由过账事件驱动

- 行业惯例：业务标志（如"已发货"）由**过账/审核事件**触发，不在草稿创建时置位
- 本设计 P0 修正即对齐此惯例
