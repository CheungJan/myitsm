## 二、方案 A 验收（预计划选 EID + 自动出库）

### 2.1 创建预计划——posid 预占 EID

**操作路径**：销售管理 → 预计划列表 → 新建

**步骤**：

1. 点击「新建」按钮，打开预计划编辑弹窗
2. 填写基本信息：
   - `plantyp` = `00`（新机开通）
   - `pos_from` = `00`（商用仓库）
   - `pos_item` = `IT001`（目标机型）
3. **方案 A 关键点**：选择机型后，「对应设备」下拉框自动加载可用 EID 列表
   - ✅ 验证：下拉框显示 `EID0000000001`（在库且未被预占）
   - ✅ 验证：已预占的 EID 不出现在下拉框中（默认 `exclude_reserved=1`）
4. 选择 `posid` = `EID0000000001`
5. 填写客户信息（custcard、custnm 等）
6. 点击「保存」

**预期结果**：

- 预计划创建成功，状态 `plan_status=00`（计划中）
- ✅ **关键验证**：进入资产管理 → EID 列表，找到 `EID0000000001`，其 `reserve_planno` 字段应显示新建的预计划号
- ✅ 再次新建预计划选同一 EID，应被拒绝（提示"EID 已被预计划 XXX 预占"）

### 2.2 呼出（可选）→ 确认 → 实施

**⚠️ 关键说明**：呼出（PlanServe）是 **可选辅助流程**，非 implement() 前置条件（对齐 PB 设计）。

**PB 设计依据**：

- 呼出需用户手动点击「请求呼出」按钮触发，非自动强制
- 预计划管理中还需勾选复选框（`call_serve`）才会生成呼出单
- 三种 `servetyp`：`1`=预计划呼出（客户部）、`2`=计划任务呼出（实施部）、`0`=客户情况确认（已注释）
- 部分模块的呼出功能已禁用（`u_serve_plan.sru` 等整个功能被注释）
- **不呼出也能走完 `00 → 02 → 04 → 01` 全流程**
- **后端 `create()` 不自动创建 PlanServe**，仅当 `call_serve=true` 时才创建（对齐 PB 勾选复选框）

**操作路径**：预计划列表

**步骤**：

1. 在预计划列表找到刚创建的计划，状态 `00`
2. （可选）点击「请求呼出」→ 生成呼出单，话务台完成回访（`status=01`）
3. 点击「确认」→ 状态 `00 → 02`（分派中）
4. 点击「实施」→ 状态 `02 → 04`（实施中）

**预期结果**：

- 状态流转：`00 → 02 → 04`（无论是否呼出均可达）
- ✅ **方案 A 关键验证**：实施后自动生成 OV=1 销售出库草稿
  - 进入仓库管理 → 出库单列表，应有一条 `refbillid=预计划号`、`invtyp=1` 的草稿
  - 出库明细应包含 `EID0000000001`（从 posid 自动带出）
- ✅ 出库单状态 `auditflg=0`（草稿，待审核）
- ⚠️ **方案 A 实施后出库单已自动生成，无需再点「出库」按钮**。误点会提示"已存在出库单 OT..."（去重校验，见 §10.2）

### 2.3 仓库审核出库单 → 释放预占

**操作路径**：仓库管理 → 出库单列表

**步骤**：

1. 找到刚生成的 OV=1 出库草稿
2. 点击「审核」→ 弹窗显示出库明细（含 EID）
3. 点击「审核通过」

**预期结果**：

- 出库单状态 `auditflg=0 → 2`（已审核）
- ✅ **关键验证**：回到资产列表，`EID0000000001` 的 `reserve_planno` 应被清空（释放预占）
- ✅ EID 状态变更：`sflg` 从 `8`（在库）变为出库状态，`whcd` 变更（如移到工程师仓待装机）
- ⚠️ 注意：此阶段设备尚未绑定门店，`CustPosRl` 未写入；要等门店关单后才写 `CustPosRl` + `type='C'`

### 2.4 计划完成——下游单据关单自动回写

**⚠️ 关键纠正**：计划完成 **不是** 手动点「完成」按钮触发的，而是下游 ITSM 单据关单时自动回写。

**正确流程**：

```
计划中(00)
  → （可选）呼出确认（话务台完成回访）
  → 确认分派（00→02）
  → 实施确认（创建下游 ITSM 单据，02→04）
  → 实施中(04)
  → 生成出库单 OV=1（仓库领机，仍为 04）
  → 仓库审核出库（设备离开仓库，sflg 变更）
  → 门店工程师执行业务并关单（to_status=5）
  → 计划完成(01) ← 关单回调自动回写
```

**操作路径**：ITSM 模块 → 对应单据列表 → 关单

**步骤**（以 plantyp=00 开通单为例）：

1. 仓库审核出库后，设备发到门店
2. 门店工程师执行安装/开通业务
3. 在 ITSM → 开通单列表找到对应单据，点击「关单」（状态 → 5）

**预期结果**：

- ✅ 开通单状态 `→ 5`（已关单）
- ✅ **自动回写**：预计划 `plan_status: 04 → 01`（计划完成）
  - 回写条件：仅当 `plan_status == '04'` 才回写，防止重复
  - 回写由 `itsm_service.py:257 _write_back_plan_status()` 触发
- ✅ 资产变更轨迹 `tmm43_eid_track` 新增 `type='C'`（设备分配）
- ✅ 客户设备关系 `tmm35_cust_pos_rl` 新建绑定（设备绑定到门店）

**设备状态三阶段**：

| 阶段 | EID 状态 | 位置 |
|------|----------|------|
| 出库前 | `whcd=仓库编码`，仓库库存 | 仓库 |
| 仓库审核出库后 | `sflg` 变更（出库单审核通过） | 出库待装机 |
| 门店关单后 | `sflg='S'`，写入 `CustPosRl` 绑定门店 | 门店设备 |

**五种 plantyp 关单回调对比**：

| plantyp | 关单回调做的事 |
|---------|---------------|
| 00 开通 | `type='C'`（分配）+ 写 `CustPosRl` + 回写 01 |
| 10 变更 | `type='T'`（转移）+ rl 转移 + 回写 01（仅 BG 子类型） |
| 20 翻新 | `type='R'`（旧机回收）+ `type='C'`（新机分配）+ rl 转移 + 回写 01 |
| 30 回收 | `type='R'`（回收）+ rl 失效 + 回写 01 |
| 40 门店关闭 | `type='R'`（批量回收）+ rl 全失效 + 回写 01 |

> **总结**：计划完成 ≠ 出库完成，而是门店工程师关单后才完成。出库只是中间环节——仓库把设备发出去，设备到了门店、工程师装好并关单，整个计划才算完成。
>
> **注**：`PlanCustService.complete()` API（`sales_service.py:632`）是独立的手动入口（测试用），实际业务流程中计划完成由下游单据关单自动触发。前端列表的「完成」按钮仅在测试/异常补救场景使用。

## 七、plantyp=10 磁卡号变更验收

### 7.1 子类型判定规则（前端实时显示）

**判定逻辑**（前端 `changeSubType` + 后端 `_build_downstream_payload` 一致）：

| 条件 | 子类型 | 说明 |
|------|--------|------|
| 选了源设备 ID（`new_posid` 有值） | **BG** | 磁卡号+设备变更（跨客户设备转移） |
| 源磁卡号 ≠ 目标磁卡号（`new_custcard` ≠ `custcard`） | **CK** | 仅磁卡号变更 |
| 源磁卡号 = 目标磁卡号，或未选源客户 | **BQ** | 信息变更（地址/电话/联系人） |

> **⚠️ 关键**：CK 的判定不是"是否选了源客户"，而是"源磁卡号与目标磁卡号是否不同"。选了源客户但目标磁卡号相同（只改地址）→ BQ。

### 7.2 BG 子类型（磁卡号+设备变更，跨客户转移）

**步骤**：

1. 新建 `plantyp=10`，选择源客户（源磁卡号 + 源设备 ID）
2. 目标客户区填写新磁卡号（与源不同）+ 新客户信息
3. 保存 → 实施
4. ITSM → 设备变更单列表，新增 `change_type='BG'` 变更单
5. 变更单关单（状态 → 5）

**预期结果**（对齐 PB `USP_PLAN_CONFRIM v_tftype=10`）：

- ✅ `tmm43_eid_track` 新增 `type='T'`（客户转移：源客户 → 目标客户）
- ✅ `tmm35_cust_pos_rl`：源客户 rl `useflg='0'`（失效），目标客户 rl `useflg='1'`（新建/激活）
- ✅ `tmm22_customers`：源客户更新磁卡号，目标客户 `useflg='0'`（合并/废弃）
- ✅ `tmm43_eid.sflg='8'`（回库入库，`USP_ASSET_C_A sltyp='BG' v_back='Y'`）
- ✅ 预计划回写 `01`

### 7.3 CK 子类型（仅磁卡号变更，同客户）

**步骤**：

1. 新建 `plantyp=10`，选择源客户（源磁卡号）
2. 目标客户区填写**不同的磁卡号**（不选源设备 ID）
3. 保存 → 实施 → 变更单关单

**预期结果**（对齐 PB `USP_PLAN_IMPLE plantyp=10 CHANGE_TYPE='CK'`）：

- ✅ `tmm16_device_change`：`change_type='CK'`，`new_store_card`=新磁卡号，`device_id`=原 POS，`new_store_id` 为空
- ✅ `tmm22_customers`：更新 `custcard`（磁卡号）、`cust_nm`、`address`（`USP_PLAN_CONFRIM`）
- ❌ 不写 `tmm43_eid_track`，不转移 `tmm35_cust_pos_rl`，不回库

### 7.4 BQ 子类型（信息变更，同客户同磁卡号）

**步骤**：

1. 新建 `plantyp=10`，选择源客户（源磁卡号）
2. 目标客户区填写**相同的磁卡号**，修改地址/电话/联系人
3. 保存 → 实施 → 变更单关单

**预期结果**（对齐 PB `USP_ITSM_EXTEND_NEW i_type='BQ'`）：

- ✅ `tmm16_device_change`：`change_type='BQ'`，`new_address`/`new_tel`/`new_contactor` 有值
- ✅ `tmm22_customers`：更新地址/电话/联系人字段
- ❌ 不变更磁卡号，不写 `tmm43_eid_track`，不转移 `tmm35_cust_pos_rl`

**步骤**：

1. 方案 A 实施后已自动生成出库单
2. 在预计划列表点击「出库」按钮

**预期结果**：

- ✅ 后端返回 400："已存在出库单 OT000001"
- ✅ 前端提示错误（不会生成第二张出库单）

### 10.3 已审核出库单反审核

**步骤**：

1. OV=1 出库单已审核通过（EID 预占已释放，并自动生成 IV=2 退货入库草稿）
2. 点击「反审核」

**预期结果**（分两种情况）：

**情况 A——关联入库单仍为草稿（auditflg='0'）**：
