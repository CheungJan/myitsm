# 生产质检与物料消耗优化实施文档

## 文档说明

本文档按**实际实施顺序**记录所有优化工作，分为四个阶段：
1. **第一阶段**：FQC 最终检测流程优化（行级判定、更换功能）
2. **第二阶段**：反审核边界情况处理（工单状态回退）
3. **第三阶段**：QC 结果页展示优化（更换标记）
4. **第四阶段**：TMS04 物料消耗扩展（成本核算核心）

## 1. 第一阶段：FQC 最终检测优化

### 1.1 背景问题

FQC（最终质量检测）需要解决以下业务场景：
- **成品与配件关联**：一个成品由多个配件组成，质检时需要保持关联关系
- **配件更换追溯**：检测发现配件不合格，现场更换新配件，需要记录"原配件+新配件"
- **行级判定**：同一物料可能部分合格、部分不合格，需要支持多行不同判定

### 1.2 优化内容

#### 1.2.1 行级判定（line-level qcstatus）

**问题**：原逻辑整个 QC 记录只有一个 `qcstatus`，无法处理同一物料部分合格的情况。

**解决方案**：每行明细独立存储 `qcstatus`。

**文件**：`app/models/warehouse.py`
```python
class QcResultDt(BaseModel):
    # ...
    qcstatus = db.Column(db.String(2), comment="质检状态")  # 新增行级判定

class QcResultEid(BaseModel):
    # ...
    qcstatus = db.Column(db.String(2), comment="质检状态")  # 新增行级判定
```

**文件**：`app/services/qc_service.py` - `audit()` 方法
```python
def _rqc(row: Any) -> str:
    """获取行级 qcstatus，无则回退主记录"""
    return row.qcstatus or qcstatus

# 按行级判定分类处理
for row in eid_rows:
    rq = _rqc(row)
    if rq in ("GA", "GB", "GC"): pass_eid.append(row)
    elif rq == "BF": scrap_eid.append(row)
    elif rq == "BH": repair_eid.append(row)
    elif rq == "TH": return_eid.append(row)
```

#### 1.2.2 批次关联与成品配件追溯

**现状**：按判定结果（GA/BF/BH）分组生成 QC 记录是正确的，因为不同判定对应不同的仓库联动类型：
- GA → 生产入库（IV=6）
- BF → 报废出库（OV=7）
- BH → 返修出库（OV=9）

**问题**：同一成品的配件可能被拆分到多个 QC 记录，结果页查看时无法识别"这个配件属于哪个成品"。

**解决方案**：利用现有 `batch_id` 字段关联同一批次的所有 QC 记录，在结果列表页实现"成品+配件"完整视图。

**数据关联设计**：
```
批次号 (batch_id) → 关联同一成品的所有 QC 记录
├─ QC记录1: 成品A (GA) → 生产入库
├─ QC记录2: 配件1 (GA) → 跟随成品入库
├─ QC记录3: 配件2 (BF) → 报废出库
└─ QC记录4: 配件2-新件 (GA) → 补料出库 → 生产入库
```

**文件**：`frontend/src/views/qc/QcResultList.vue` - 新增批次视图模式
```javascript
// 按批次分组展示
```

#### 1.2.3 更换按钮功能

**业务场景**：检测发现配件 BF（报废），现场从仓库领新配件更换，需要记录：
- 原配件：BF 判定，标记为"已更换"
- 新配件：GA 判定，标记为"新件"

## 2. 第二阶段：反审核优化

### 2.1 背景问题

FQC 审核后工单状态变为 `COMPLETED`，原反审核逻辑仅作废下游单据，**不回退工单状态**。这导致：
- 反审核后工单仍显示"已完成"
- 重新审核时工单状态混乱
- 无法正确追踪工单实际进度

### 2.2 解决方案

**文件**：`app/services/qc_service.py` - `unaudit()` 方法

```python
@staticmethod
def unaudit(qcbillid: str, auditor: str) -> dict[str, object]:
    """反审核 QC：作废下游单据 + 回退工单状态"""
    
    # 1. 检查下游单据是否已审核（已有逻辑）
    has_audited = db.session.query(StockIn).filter(...).first() \
               or db.session.query(StockOut).filter(...).first()
    if has_audited:
        return {"success": False, "error": "下游出入库单据已审核，不可反审核"}
    
    # 2. 作废下游草稿单据（已有逻辑）
    db.session.query(StockIn).filter(...).update({"auditflg": "V"})
    db.session.query(StockOut).filter(...).update({"auditflg": "V"})
    
    # 3. 回退 QC 状态（已有逻辑）
    qc.auditflg = "0"
    qc.auditman = ""
    qc.auditdate = None
    
    # 4. 【新增】回退 FQC 工单状态
    _qc_ref = qc.refbillid or ""
    if _qc_ref.startswith("WO"):
        from app.models.mes import WorkOrder
        _wo = WorkOrder.query.get(_qc_ref)
        if _wo and _wo.status == "COMPLETED":
            # 关键：检查是否还有其他已审核的QC记录关联此工单
            other_qc = db.session.query(QcResult).filter(
                QcResult.refbillid == _qc_ref,
                QcResult.auditflg == "1",
                QcResult.qcbillid != qcbillid
            ).first()
            if not other_qc:
                # 无其他已审QC，说明这是最后一个，回退工单状态
                _wo.status = "QC_PENDING"
                _wo.upddate = dt_parse.now(UTC)
    
    db.session.commit()
    return {"success": True}
```

### 2.3 关键点

| 检查项 | 说明 |
|--------|------|
| 工单状态检查 | 仅当 `_wo.status == "COMPLETED"` 时才回退 |
| 其他QC检查 | 检查是否还有其他已审核的QC记录，避免重复回退 |
| 回退目标状态 | `QC_PENDING`（保持质检状态，而非 `IN_PROGRESS`） |
| 事务一致性 | 与作废下游单据在同一事务中提交 |

## 3. 第三阶段：QC 结果页展示优化

### 3.1 背景

FQC 过程中存在配件更换，需要在结果页清晰展示：
- 哪个配件被更换了
- 更换后的新配件是什么
- 批次物料明细（details）和序列号明细（eid_details）都需要显示
- 物料类型判断应基于 `typflg` 和 `consume` 字段，而非简单的 itemcd 比较

### 3.2 问题发现

**问题1**：原代码只显示 `eid_details`（序列号明细），导致批次物料类型 QC 记录（如 QC260610030）不显示入库明细。

**问题2**：物料类型判断使用 `dt.itemcd == qc.itemcd`，在纯配件/耗材场景误判（如 QC260610027 配件 BS4201 被误判为成品，QC260610028 耗材 BS42L1 被误判为成品）。

**根本原因**：物料分类应来自 `tmm12_items.typflg`（成品/配件）和 `consume`（耗材），而非简单的 itemcd 匹配。

### 3.3 解决方案

#### 3.3.1 后端：返回物料类型字段

**文件**：`app/services/qc_service.py` - `get_batch_details()` 方法

**物料类型判断函数**：
```typescript
// 根据 typflg 和 consume 判断物料类型
function getItemTypeLabel(item: any): string {
    if (item.consume === '1') return '耗材'
    if (item.typflg === '1') return '成品'
    return '配件'
}

// 获取最终有效的 EID（排除已更换的）
function getActiveEids(record: any): any[] {
  return (record.eid_details || []).filter((e: any) => !e.is_replaced)
}

// 检查是否有更换历史
function hasReplacementHistory(record: any): boolean {
  const eids = record.eid_details || []
  return eids.some((e: any) => e.is_replacement || e.is_replaced)
}

// 获取更换历史时间线（按时间排序）
function getHistoryTimeline(records: any[]): any[] {
  return records
    .map((r: any) => ({
      qcbillid: r.qcbillid,
      gendate: r.gendate,
      qcstatus: r.qcstatus,
      details: r.details || [],
      eid_details: r.eid_details || []
    }))
    .sort((a: any, b: any) => a.gendate.localeCompare(b.gendate))
}
```

## 4. 第四阶段：TMS04 物料消耗扩展（核心）

### 4.1 背景与目标

原 TMS04 物料消耗表仅记录"计划用量"和"实际用量"，无法：
- 追溯物料消耗的来源（定额/补料/报废/返修）
- 关联仓库单据和质检记录
- 核算工单实际材料成本

**目标**：
1. 全生命周期追踪：覆盖从定额领料到完工的所有物料变动
2. 自动成本核算：根据物料标准价格自动计算成本
3. 来源可追溯：关联仓库单据（OV/IV）和质检单（QC）

## 7. 技术要点总结

1. **数据一致性**：4个写入点统一使用 `Price` 模型查询单价，保证成本核算口径一致
2. **可扩展性**：`consume_type` 预留其他类型，支持未来扩展
3. **可追溯性**：通过 `ref_bill_id` 和 `ref_qc_id` 实现全链路追溯
4. **兼容性**：单价字段允许为空，现有数据无价格时不影响功能
5. **事务一致性**：所有写入操作在同一事务中提交，保证数据一致性

### 6.1 工单取消清理

**文件**：`app/services/mes_service.py` — `transition()` 方法 CANCELLED 分支

取消时自动处理：

| OV=8 状态 | 处理 |
|-----------|------|
| 草稿 (auditflg='0') | 直接作废 (→'V') |
| 已审核 (auditflg='2') | 生成 IV=3 退货草稿对冲 + TMS04 consume_type='5' |

QC_PENDING 额外处理：
- QC 已审核 → 阻止取消
- 下游 IV/OV 已审核 → 阻止取消
- QC 草稿/退回 → 作废 + 下游草稿作废

**文件**：`app/services/mes_service.py` — `_create_production_outbound_draft()` 去重修复
- 加 `useflg='1'` 过滤，避免已作废的 OV=8 阻塞重生成
