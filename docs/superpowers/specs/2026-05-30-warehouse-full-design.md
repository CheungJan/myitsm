## 1. 设计原则

### 1.1 核心原则

```
所有出入库操作优先关联上游业务单据。
能自动生成就自动生成，不能自动的通过单据选择器关联。
无上游单据时（临时借用、备件领用、样品出库等）：
    ├─ 选仓库 → 展示该仓库存列表 → 搜索过滤 → 勾选出库
    ├─ 库存列表按物料编码/名称展示，含当前数量和可用EID
    ├─ 支持批次模式（填数量）和EID模式（选序列号）
    └─ 行业参考：SAP用Reservation预留单兜底无单领料，Odoo用Internal Transfer
```

> **当前阶段不引入物料树**：物料树适用于SKU上万的大型WMS。当前系统SKU规模下，仓库库存列表+搜索比分类树更实用。后续SKU增长后可在库存列表上方加分类筛选，不是独立视图。

### 1.2 出入库本质

> 出入库 = 库存数量变更 + 物料状态变更 + （可选）设备状态变更

根据操作模式（批次 vs EID），影响不同表：

| 模式         | 影响表                                   | 说明                                                         |
| ------------ | ---------------------------------------- | ------------------------------------------------------------ |
| **批次模式** | `TWH11_DETAIL`（批次库存）               | 更新该仓库该物料的库存数量（whcd + itemcd + itemqty）        |
| **EID模式**  | `TWH11_DETAIL` + `TMM43_EID`（设备主表） | 批次模式所有操作 + 同步更新设备所在仓库（whcd）和设备状态（sflg/qcflg） |

**物料状态（itemtyp）**—— 对应系统字典 `SS`（商品属性）：

| 编码   | 名称     | 说明         |
| ------ | -------- | ------------ |
| ZC / 1 | 正常     | 正常可用商品 |
| DC     | 待处理   | 待处理商品   |
| DJ     | 待检     | 待质检商品   |
| TH     | 退货     | 退货商品     |
| JP     | 实物奖励 | 赠品/奖励品  |
| TS     | 特殊     | 特殊商品     |
| YP     | 样品     | 样品         |
| 2      | 停用     | 已停用       |
| 3      | 维修中   | 维修中       |
| 4      | 报废     | 已报废       |

不同状态的物料可能存放在不同仓库或按不同规则出入库。

**设备状态（TMM43_EID 表）**：

| 字段    | 说明     | 取值及含义                                                   |
| ------- | -------- | ------------------------------------------------------------ |
| `sflg`  | 设备状态 | `0`=新品已检, `1`=已使用, `2`=已报废, `3`=待检, `4`=已退回, `5`=已检, `6`=检验中, `7`=生产中, `8`=在库, `9`=出库, `S`=销售出库 |
| `qcflg` | 质检状态 | `GA`=绿A, `GB`=绿B, `GC`=绿C, `BH`=坏, `DJ`=待检, `BF`=报废  |
| `whcd`  | 所在仓库 | 仓库代码（如 L1=正式仓, L2=质检仓, L3=工程师仓等）           |

**EID 生成时机**：

- 采购入库时：仅有物料编码，无EID（批次模式）
- 质检通过后：标签管理生成序列号 → 关联 `TMM43_EID`（转为EID模式）
- 耗材/散料：永远批次模式，无EID

### 1.3 自动联动优先级

```
上游单据审核通过
    │
    ├─ 能确定仓库+明细 → 完全自动生成 + 自动审核
    ├─ 能确定明细但仓库待定 → 生成草稿，人工选仓库后审核
    ├─ 能提供单据选择器 → 选单后自动填明细
    └─ 不能提供单据选择器 → 手动模式：选仓 → 库存列表 → 勾选出库
```

> **核心差异**：新系统按业务语义重新编号，PB 的 invtyp 与 IV/OV 字典**不是 1:1 映射**。代码中全部使用 IV/OV 字典码，PB 源码码仅作历史参考。
>
> ### 2.4 出入库本质分类：移动型 vs 转换型
>
> | 维度     | 移动型                                       | 转换型                                       |
> | -------- | -------------------------------------------- | -------------------------------------------- |
> | **代表** | OV=2 服务领用、OV=3 调拨、OV=4 借出          | OV=8 生产出库、OV=10 翻新出库                 |
> | **物品身份** | 不变（同一个 EID、同一批物料）            | 变了（配件→成品、旧 EID→新 EID）              |
> | **库存变化** | 源仓 -N，目的仓 +N，**总量不变**           | 配件/旧品消失，成品/新品出现，**品种结构变了** |
> | **对应入库** | OV=3→IV=4 调拨入库（同物确认）              | OV=8→IV=8 生产入库、OV=10→IV=6 翻新入库     |
> | **EID 处理** | whcd 更新即可                               | 旧 EID 离库/报废，新 EID 生成                 |
> | **单据特征** | 出库单含 `targetwhcd`，审核直接入目的仓      | 出库无 `targetwhcd`，入库时重新生成身份       |
>
> **服务领用 (OV=2) 审核细节**：
> - EID 模式：`TMM43_EID.whcd = targetwhcd`（工程师仓），`sflg = '1'`（持有）
> - 批次模式：源仓 `update_balance(-N)`，目的仓 `update_balance(+N)`，双流水记录
> - OV=2 无对应入库单，审核一步完成源仓出+目的仓入
>
> **翻新出库 (OV=10) 生命周期跟踪**（待实施）：
> - `TMM43_EID` 新增 `ref_eid` 字段，记录来源 EID
> - 翻新出库审核：旧 EID 标记 `sflg = '7'`（翻新中）
> - 翻新入库 (IV=6)：生成新 EID，写入 `ref_eid = 旧EID`，形成溯源链
> - 查询时沿 `ref_eid` 递归追溯完整历史

### 2.5 盘盈盘亏（独立模块，不走 invtyp）

盘盈/盘亏使用独立的损益单体系（PB: `u_wh_overlost_audit`，新系统: `OverLostList`），调用 `USP_OVERLOST_AUDIT` 存储过程，不走 TWH13/TWH15 的 invtyp 体系。

| 表名                | 说明                                                 |
| ------------------- | ---------------------------------------------------- |
| `TWH17_OVERLOST`    | 损益主表（olbillid, oltyp, olsign, optyp, auditflg） |
| `TWH18_OVERLOSTDT`  | 损益明细（批次模式）                                 |
| `TWH18_OVERLOSTEID` | 损益明细（EID模式）                                  |

## 3. 批次模式 vs EID模式

### 3.1 出入库明细表设计

#### PB 原始设计

| 方向     | 模式 | 明细表          | 说明                                              |
| -------- | ---- | --------------- | ------------------------------------------------- |
| **入库** | 批次 | TWH14_CHECKINDT | PB 原版无 eid 列，EID 追踪通过 TMM43_EID 单独处理 |
| **出库** | 批次 | TWH16_OUTDTPRD  | 无 eid 字段                                       |
| **出库** | EID  | TWH16_OUTDTEID  | 有 eid 字段，精确追踪每台设备                     |

> **PB 原始特点**：入库侧只有批次模式明细表，没有 EID 入库明细表。EID 设备的入库通过更新 `TMM43_EID.whcd` + 更新 `TWH11_DETAIL` 库存完成，不写入独立的 EID 明细记录。

#### 新系统改进（2026-05-28 迁移 `e5f6a7b8c9d0`）

TWH14_CHECKINDT 新增 `eid` / `seid` 列，入库侧也支持 EID 模式：

> **已知限制**：历史数据未回填。PB 时期的 EID 入库追踪仍通过 `TMM43_EID.whcd` 间接查询，新产生的入库记录才会写入 `TWH14.eid`。两种机制并存，不影响业务。

| optyp | 模式 | 出库明细表     | 入库明细表                | 适用对象         |
| ----- | ---- | -------------- | ------------------------- | ---------------- |
| `PC`  | 批次 | TWH16_OUTDTPRD | TWH14_CHECKINDT（eid=空） | 无EID的散料/来料 |
| `ID`  | EID  | TWH16_OUTDTEID | TWH14_CHECKINDT（eid≠空） | 有EID的设备/配件 |

### 3.2 模式选择规则

| 物料类型                   | 模式 | 说明              |
| -------------------------- | ---- | ----------------- |
| 整机（POS机等）            | EID  | 每台有唯一序列号  |
| 关键配件（读卡器、主板等） | EID  | 有EID需精确追踪   |
| 散料（线材、螺丝等）       | 批次 | 无EID，按数量管理 |
| 包装/耗材                  | 批次 | 无需精确追踪      |

### 3.3 出库表结构：是否合并为一张表？

出库侧当前沿用 PB 的分离设计（TWH16_OUTDTPRD + TWH16_OUTDTEID）。入库侧已通过迁移添加 eid 列实现单表双模式，无需讨论。

| 方案                 | 优点                                        | 缺点                            |
| -------------------- | ------------------------------------------- | ------------------------------- |
| **保持分离（当前）** | 与PB一致，迁移简单；查询无需过滤eid是否为空 | 需维护两套模型                  |
| **合并为一张表**     | 简化模型，减少代码                          | 历史数据迁移复杂；需过滤eid空值 |

**建议**：保持分离。与PB源码逻辑一致，减少重构风险。

## 5. 各业务场景详细设计

### 5.1 生产流程（MES工单→BOM领料→生产出库→质检结果→生产入库）

#### 流程概述

```
生产出库按BOM导入（未来由MES工单触发）
    ↓
按BOM结构生成生产出库草稿（批次/EID模式）
    ↓
生产出库审核（领取配件/来料）
    ↓
组装测试
    ↓
生成设备标签/生产质检结果
    ↓
按质检结果生成生产入库草稿
    ↓
生产入库（成品入库）
```

> **PB源码依据**：PB 中没有“MES工单释放/领料”这个叫法。`w_wh_scout_input` 窗口标题为生产出库单录入，按钮为“按BOM导入”，`is_invtyp='4'`，保存后调用 `usp_wh_out('4', outbillid, opercd, ...)`；`w_wh_scin_input` 为生产入库窗口，`is_invtyp='4'`，保存后调用 `usp_wh_in('4', inbillid, opercd, ...)`。质检模块通过选择生产出库单生成质检结果，生产入库再选择质检结果单回填入库明细。

#### BOM领料模式

| 模式     | optyp | 适用场景        | 明细表         | 操作方式                      |
| -------- | ----- | --------------- | -------------- | ----------------------------- |
| 批次模式 | PC    | 耗材/未质检来料 | TWH16_OUTDTPRD | 按物料编码+数量，直接组装测试 |
| EID模式  | ID    | 已质检物料      | TWH16_OUTDTEID | 按EID序列号，精确追踪每个配件 |

#### 关键节点与 invtyp 对应

| 节点              | 单据类型     | invtyp     | 自动生成          | 关联字段           | 说明                                                        |
| ----------------- | ------------ | ---------- | ----------------- | ------------------ | ----------------------------------------------------------- |
| 生产出库按BOM导入 | 生产出库草稿 | OV=8(其他) | 规划自动          | refbillid=工单号   | PB为手工生产出库+按BOM导入；当前重构代码尚未打通MES自动触发 |
| 生产出库审核      | 生产出库单   | OV=8(其他) | 手动审核          | outbillid          | 扣减领料仓库存；EID模式同步设备仓库                         |
| 生产质检结果确认  | 生产入库草稿 | IV=8(其他) | 规划自动          | refbillid=质检单号 | PB中通过选择质检结果单带入明细                              |
| 生产入库审核      | 生产入库单   | IV=8(其他) | 手动审核/规划自动 | inbillid           | 增加成品库存；EID模式同步设备仓库和质检状态                 |

#### BOM结构自动填充

- **批次模式**：根据BOM表自动填充物料编码、数量、批次号
- **EID模式**：根据BOM表+质检合格物料自动填充EID序列号
- **标签生成**：组装完成后生成新设备EID，关联BOM中的配件EID

#### 设备标签管理

- 组装完成后生成新设备EID标签
- 标签关联BOM中的所有配件EID（EID模式）或批次信息（批次模式）
- 标签信息包括：设备EID、BOM版本、生产日期、质检状态

#### 质检与生产入库关系

- 生产出库单是生产质检结果的数据来源之一
- 质检结果记录在 `TQC10_RESULT`、`TQC11_RESULTDT`、`TQC11_RESULTEID`
- 生产入库优先关联质检结果单，而不是直接关联生产出库单
- 质检合格（`qcstatus='GA'/'GB'/'GC'`）→ 进入成品/正式仓
- 质检不合格（`qcstatus='BH'`）→ 返修或报废处理，不直接作为合格成品入库

### 5.2 销售实施流程（预计划→话务核实→实施单→设备领用→安装完成→销售生成）

#### 流程概述

```

    ↓
```

**过滤规则**（`find_service_returnable_items` 五层过滤）：

| 层 | 条件 | 排除 | 实现 |
|------|------|------|------|
| 1 | `in_wh IS DISTINCT FROM '1'` | 已入库 | DB |
| 2 | `in_wh IS DISTINCT FROM '2'` | 已标记不入库 | DB |
| 3 | `asset_owner != '01'`（ppt_code修正为'00'） | 客户资产 | DB |
| 4 | `tmm12_items.consume != '1'` | 耗材（数据线/支架等） | DB |
| 5 | `old_accessories_id` 在 TMM43_EID 中存在 | 无EID记录 | 内存 |

**资产属性修正**：`tmm22_customers.ppt_code IN ('9','11','12','13','14','15')` → `'00'`（自有），其他→`'01'`（客户）

### 6.5 联动单据一致性规范（新增联动时必须遵循）

所有出入库联动必须实现以下三项基本保护：

#### 6.5.1 草稿复用（同一来源单据不重复生成草稿）

```
手动新建 → 同一 refbillid + invtyp + auditflg='0' 已存在
           → 更新已有草稿，不新建
```

**必须修改的位置**：
1. `StockInService.create` — `ref_rgstbillid` 赋值行：已覆盖 `["1","4","5","8","9"]`
2. `StockOutService.create` — `existing_draft` 查询条件：已覆盖 `"6"`

#### 6.5.2 自动联动去重（审核时避免生成重复草稿）

```
审核触发 → 调用 StockInService.create(refbillid=X, invtyp=Y)
           → 自动沿用 §6.5.1 的草稿复用逻辑
```

> 无需额外代码。`StockInService.create` 的草稿复用逻辑覆盖了手动新建和自动联动两种路径。

#### 6.5.3 作废规则

```
标准流程：源单据审核 → 自动生成目的单据草稿
所以：源单据草稿时，目的单据尚未生成
```

| 源单据状态 | 目的单据状态 | 作废规则 | 理由 |
|-----------|-------------|---------|------|
| 草稿 | 无 | ✅ 源单据直接作废 | 未生成目的单据，无影响 |
| 已审核 | 草稿 | ✅ 目的单据可**独立**作废，不影响源单据 | 目的单据未生效，清理合理；源单据库存已扣，不可回滚 |
| 已审核 | 已审核 | ❌ 不可作废，需冲销/反审核 | 双方均已生效 |

**禁止的行为**：
- ❌ 源单据作废联动目的单据 — 源审核后不可作废；若为草稿则无目的单据
- ❌ 目的单据已审核随意作废 — 库存已生效，需走反审核

**必须修改的位置**（仅边界保护）：
- `StockOutService.void` — `linked_audited` 查询：`invtyp.in_(["4","8","9"])` 已覆盖调拨/生产/返修
