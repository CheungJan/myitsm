## 1. 数据确认（业务回馈）模块

### 1.1 模块概述

**功能定位**: 接收ITSM系统的业务回馈数据，进行确认处理，实现ITSM与CCGL系统的数据同步。

**所属模块**: 数据交换模块（trans.pbl）

**主要文件**:
- `trans.pbl/u_trans_in.sru` - 数据确认主界面
- `trans.pbl/u_trans_in_ywhk.sru` - 数据确认（维护版）
- `trans.pbl/u_trans_in_error.sru` - 错误处理
- `trans.pbl/d_trans_in_l_open.srd` - 业务回馈单数据窗口
- `trans.pbl/d_trans_in_l_item.srd` - 配件变更单数据窗口

### 1.2 业务类型区分

数据确认模块根据`CLASSNM`字段区分两种业务类型：

| 业务类型 | CLASSNM值 | 数据源表 | 数据窗口 | 主要用途 |
|---------|-----------|---------|---------|---------|
| **业务回馈单** | '业务回馈单' | SM_IN_OPEN_RESULT | d_trans_in_l_open | ITSM开通工单回馈结果确认 |
| **配件变更单** | '配件变更单' | SM_IN_PART_CHANGE | d_trans_in_l_item | ITSM维护单配件更换记录确认 |

### 1.3 数据表结构

#### 1.3.1 SM_IN_OPEN_RESULT（业务回馈结果表）

**用途**: 存储ITSM系统开通工单的回馈结果

**关键字段**:

| 字段名 | 类型 | 说明 | 取值范围 |
|--------|------|------|---------|
| id | NUMBER | ITSM自增号（主键） | - |
| plan_no | VARCHAR(64) | 计划单号 | - |
| case_no | VARCHAR(64) | 工单号 | - |
| cardcode | VARCHAR(64) | 门店磁卡号 | - |
| serialno | VARCHAR(128) | 设备序列号（EID） | - |
| completeddate | TIMESTAMP | 完工时间 | - |
| result | VARCHAR(512) | 反馈信息 | - |
| insert_time | TIMESTAMP | ITSM写入时间 | - |
| syn_time | TIMESTAMP | CCGL读取时间 | - |
| sys_status | NUMBER | 系统状态 | 1=待确认，2=已确认 |

**查询条件**:
```sql
WHERE SM_IN_OPEN_RESULT.SYS_STATUS = 1  -- 仅查询待确认记录
```

**关联表**:
- `TSL01_EXTEND` - 获取销售类型（sltyp）
- `PLAN_CUST` - 获取计划客户类型（plantyp）

#### 1.3.2 SM_IN_PART_CHANGE（配件更换记录表）

**用途**: 存储ITSM维护单中的配件更换记录

**关键字段**:

| 字段名 | 类型 | 说明 | 取值范围 |
|--------|------|------|---------|
| id | NUMBER | ITSM自增号（主键） | - |
| changetype | NUMBER | 更换类型 | 1=新增，2=调换，3=作废，4=返回，5=整机 |
| name | VARCHAR(128) | 配件名称 | - |
| serialno | VARCHAR(128) | 配件序列号（EID） | - |
| model | VARCHAR(128) | 配件编码 | - |
| old_name | VARCHAR(128) | 原配件名称 | - |
| old_serialno | VARCHAR(128) | 原配件序列号 | - |
| old_model | VARCHAR(128) | 原配件编码 | - |
| case_no | VARCHAR(258) | 工单号 | - |
| insert_time | TIMESTAMP | ITSM写入时间 | - |
| syn_time | TIMESTAMP | CCGL读取时间 | - |
| sys_status | NUMBER | 系统状态 | 1=未处理，2=已处理，5=已作废（手工），9=已作废（系统） |
| operflg | CHAR(1) | 入库标志 | 0=不入库，1=入库 |
| memo | VARCHAR(1000) | 备注 | - |

**查询条件**:
```sql
WHERE SM_IN_PART_CHANGE.SYS_STATUS = 2  -- 仅查询已处理记录
```

### 1.4 数据流向

#### 1.4.1 业务回馈单数据流

```
ITSM系统开通工单完成
    ↓
写入SM_IN_OPEN_RESULT（SYS_STATUS=1）
    ↓
CCGL数据确认模块查询待确认记录
    ↓
用户确认处理
    ↓
更新SM_IN_OPEN_RESULT.SYS_STATUS=2
    ↓
（可选）回写ITSM系统状态
```

#### 1.4.2 配件变更单数据流

```
ITSM维护单配件更换完成
    ↓
写入SM_IN_PART_CHANGE（SYS_STATUS=2，operflg=1表示需入库）
    ↓
CCGL数据确认模块查询已处理记录
    ↓
用户确认处理
    ↓
更新SM_IN_PART_CHANGE.SYS_STATUS=5（已作废手工）
    ↓
（若operflg=1）触发维护入库操作
    ↓
关联TWH13_IN入库单（REFBILLID=SM_IN_PART_CHANGE.ID）
```

### 1.5 operflg字段与工程师个人仓库

**SM_IN_PART_CHANGE.operflg字段**：
- `0` = 不入库：仅记录配件变更，不触发库存操作
- `1` = 入库：触发维护入库操作，将配件从工程师个人仓库转移到正式仓库

#### 1.5.1 operflg=1（入库）时的数据流

```
ITSM维护单配件更换完成
    ↓
写入SM_IN_PART_CHANGE（sys_status=2, operflg=1）
    ↓
CCGL数据确认模块确认
    ↓
更新SM_IN_PART_CHANGE.sys_status=5
    ↓
自动创建维护入库单（TWH13_IN，invtyp='3'，refbillid=SM_IN_PART_CHANGE.ID）
    ↓
更新TMM43_EID（工程师个人仓库设备表）
    ├─ sflg状态变更（从工程师持有状态变为待检状态）
    ├─ whcd变更（从工程师仓库代码变更为正式仓库代码）
    └─ qcflg='待检'（质检标志）
    ↓
写入TWH14_CHECKINDT（入库明细表）
    ↓
审核后更新TWH11_DETAIL（批次库存表，增加库存数量）
```

#### 1.5.2 operflg=0（不入库）时的数据流

```
ITSM维护单配件更换完成
    ↓
写入SM_IN_PART_CHANGE（sys_status=2, operflg=0）
    ↓
CCGL数据确认模块确认
    ↓
更新SM_IN_PART_CHANGE.sys_status=5
    ↓
不触发任何库存操作
    ↓
配件仍保留在工程师个人仓库（TMM43_EID.sflg保持原状态）
```

#### 1.5.3 TMM43_EID表（工程师个人仓库设备表）

**用途**: 存储工程师个人持有的设备/配件信息，相当于工程师的个人仓库

**关键字段**:

| 字段名 | 类型 | 说明 |
|--------|------|------|
| eid | CHAR(13) | 设备序列号（主键） |
| itemcd | CHAR(6) | 配件编码 |
| sflg | CHAR(1) | 设备状态（工程师个人仓库状态） |
| whcd | CHAR(2) | 仓库代码（工程师仓库→正式仓库） |
| qcflg | CHAR(2) | 质检标志 |
| prddate | DATETIME | 生产日期 |
| itemtyp | CHAR(2) | 商品属性 |
| opercd | CHAR(6) | 操作员（工程师） |
| useflg | CHAR(1) | 使用标志 |
| etyp | CHAR(1) | 设备类型 |
| refid | CHAR(8) | 引用ID |

**operflg操作涉及的表**:

| 表名 | 字段 | 作用 |
|------|------|------|
| **SM_IN_PART_CHANGE** | operflg | 控制是否触发入库操作 |
| **TMM43_EID** | sflg | 设备状态（工程师个人仓库状态） |
| **TMM43_EID** | whcd | 仓库代码（工程师仓库→正式仓库） |
| **TMM43_EID** | qcflg | 质检标志（入库后设为待检） |
| **TWH13_IN** | refbillid | 关联SM_IN_PART_CHANGE.ID |
| **TWH14_CHECKINDT** | - | 入库明细表 |
| **TWH11_DETAIL** | itemqty | 批次库存数量 |

**总结**:
- **配件入库操作（operflg=1）**: 从工程师个人仓库（TMM43_EID，sflg标识持有状态）转移到正式仓库（TMM43_EID.whcd变更，sflg变更为待检状态），通过TWH13_IN维护入库单记录，最终进入TWH11_DETAIL批次库存表
- **配件不入库操作（operflg=0）**: 仅记录变更信息，配件仍保留在工程师个人仓库，不影响CCGL库存

### 1.6 关键业务流程

#### 1.6.1 数据确认操作

**业务回馈单确认**:
```sql
-- 确认后更新状态
UPDATE SM_IN_OPEN_RESULT
SET SYS_STATUS = 2, SYN_TIME = SYSDATE
WHERE ID = :ll_id;
```

**配件变更单确认**:
```sql
-- 确认后标记为已作废（手工）
UPDATE SM_IN_PART_CHANGE
SET SYS_STATUS = '5'
WHERE ID = :ll_id;
```

#### 1.6.2 错误处理回退

```sql
-- 回退到未处理状态
UPDATE SM_IN_PART_CHANGE
SET SYS_STATUS = '1'
WHERE ID = :ll_id;
```

#### 1.6.3 配件变更单与入库单关联

入库单表`TWH13_IN`通过`REFBILLID`字段关联配件变更记录：

```sql
-- 入库单查询关联
SELECT TWH13_IN.*, SM_IN_PART_CHANGE.CASE_NO
FROM TWH13_IN
LEFT OUTER JOIN SM_IN_PART_CHANGE
ON SM_IN_PART_CHANGE.ID = TO_NUMBER(TWH13_IN.REFBILLID)
WHERE TWH13_IN.INVTYP = '3';  -- 维护类型
```

## 2. 维护入库/出库模块

**功能定位**: 仓库内部维护性操作，处理维修备件、维护消耗品等非业务性出入库，直接修改库存数量。

**所属模块**: 仓库管理模块（wh_syc.pbl）

**主要文件**:
- `wh_syc.pbl/w_wh_whin_input.srw` - 维护入库单录入

### 2.3 数据流向

#### 2.3.1 维护入库数据流

```
用户创建维护入库单
    ↓
查询TWH11_DETAIL（批次库存）获取可用批次
    ↓
查询TMM12_ITEMS（商品信息）获取商品详情
    ↓
写入TWH13_IN（入库主表，invtyp='3'）
    ↓
写入TWH14_CHECKINDT（入库明细表）
    ↓
审核通过后
    ↓
更新TWH11_DETAIL（批次库存表，增加库存数量）
    ↓
更新TWH13_IN.USEFLG='1'（已入库）
```

#### 2.3.2 维护出库数据流

```
用户创建维护出库单
    ↓
选择出库方式（optyp）
    ↓
    ├─ 批次出库（optyp='PC'）
    │   ↓
    │   查询TWH11_DETAIL（批次库存）获取可用批次
    │   ↓
    │   写入TWH15_OUT（出库主表，invtyp='3', optyp='PC'）
    │   ↓
    │   写入TWH16_OUTDT（批次出库明细表）
    │
    └─ EID出库（optyp='ID'）
        ↓
        查询TMM43_EID（设备表）验证设备状态（sflg='2'）
        ↓
        写入TWH15_OUT（出库主表，invtyp='3', optyp='ID'）
        ↓
        写入TWH16_OUTDTEID（EID出库明细表）
    ↓
审核通过后
    ↓
更新TWH11_DETAIL（批次库存表，减少库存数量）
    ↓
更新TWH15_OUT.USEFLG='1'（已出库）
```

#### 2.3.3 配件变更单触发维护入库数据流

```
ITSM配件变更完成
    ↓
写入SM_IN_PART_CHANGE（sys_status=2, operflg=1）
    ↓
CCGL数据确认模块确认
    ↓
更新SM_IN_PART_CHANGE.sys_status=5
    ↓
自动创建维护入库单
    ↓
写入TWH13_IN（invtyp='3', refbillid=SM_IN_PART_CHANGE.ID）
    ↓
写入TWH14_CHECKINDT（入库明细）
    ↓
审核后更新TWH11_DETAIL库存
```

### 2.4 关键业务流程

```sql
FROM TWH11_DETAIL
WHERE itemcd = :as_itemcd AND whcd = :as_whcd;
```

**获取最早生产日期**:
```sql
SELECT MIN(prddate) INTO :ldt_Proddate
FROM TWH11_DETAIL
WHERE itemcd = :as_Itemcd AND whcd = :as_whcd;
```

**生成入库单号**:
```sql
-- 调用取号函数获取inbillid
```

**保存入库单**:
```sql
-- 写入主表
INSERT INTO TWH13_IN (inbillid, indate, whcd, invtyp, refbillid, opercd, gendate, useflg)
VALUES (:ls_RgstBillid, SYSDATE, :ls_whcd, '3', :ls_refbillid, :ls_opercd, SYSDATE, '0');

-- 写入明细表
INSERT INTO TWH14_CHECKINDT (inbillid, lineno, itemcd, prddate, inqty)
VALUES (:ls_inbillid, :li_lineno, :ls_itemcd, :ldt_prddate, :ldc_inqty);
```

#### 2.4.2 维护出库单创建

**批次出库查询**:
```sql
SELECT itemcd, prddate, itemqty, itemtyp
FROM TWH11_DETAIL
WHERE itemcd = :as_itemcd AND whcd = :as_whcd AND itemqty > 0;
```

**EID出库验证**:
```sql
SELECT sflg INTO :ls_status
FROM TMM43_EID
WHERE eid = :ls_eid;

-- 验证设备状态必须为'2'
IF ls_status <> '2' THEN
    RAISE ERROR '设备状态异常';
END IF;
```

**保存出库单**:
```sql
-- 批次出库
INSERT INTO TWH15_OUT (outbillid, outdate, whcd, invtyp, optyp, opercd, gendate, useflg)
VALUES (:ls_RgstBillid, SYSDATE, :ls_whcd, '3', 'PC', :ls_opercd, SYSDATE, '0');

INSERT INTO TWH16_OUTDT (outbillid, lineno, itemcd, prddate, outqty)
VALUES (:ls_outbillid, :li_lineno, :ls_itemcd, :ldt_prddate, :ldc_outqty);

-- EID出库
INSERT INTO TWH15_OUT (outbillid, outdate, whcd, invtyp, optyp, opercd, gendate, useflg)
VALUES (:ls_RgstBillid, SYSDATE, :ls_whcd, '3', 'ID', :ls_opercd, SYSDATE, '0');

INSERT INTO TWH16_OUTDTEID (outbillid, lineno, itemcd, prddate, eid, outqty)
VALUES (:ls_outbillid, :li_lineno, :ls_itemcd, :ldt_prddate, :ls_eid, :ldc_outqty);
```

#### 2.4.3 库存更新

**入库增加库存**:
```sql
UPDATE TWH11_DETAIL
SET itemqty = itemqty + :ldc_inqty
WHERE itemcd = :ls_itemcd AND prddate = :ldt_prddate AND whcd = :ls_whcd;
```

**出库减少库存**:
```sql
UPDATE TWH11_DETAIL
SET itemqty = itemqty - :ldc_outqty
WHERE itemcd = :ls_itemcd AND prddate = :ldt_prddate AND whcd = :ls_whcd;
```

### 2.5 单号生成规则

#### 2.5.1 单号生成机制

**存储过程**: `UF_GET_BILLNOU`

**调用位置**: `app_objects.pbl/nvo_appservice.sru`

**调用代码**:
```powerbuilder
// 维护入库单号生成
li_Rec = lnv_AppSrv.of_GetBillNo('IN', ls_RgstBillid)

// 维护出库单号生成
li_Rec = lnv_AppSrv.of_GetBillNo('OT', ls_RgstBillid)
```

#### 2.5.2 存储过程逻辑

**参数**:
- `IN_BILLTYPE`: 业务类型代码（如'IN'入库，'OT'出库）

**处理流程**:
```sql
-- 1. 从单号控制表获取当前单号
SELECT CurBillId, MaxBillId
INTO v_CurBillNo, v_MaxBillNo
FROM tmm34_IdMaster
WHERE IdTyp = IN_BILLTYPE;

-- 2. 检查是否达到最大值
IF v_CurBillNo >= v_MaxBillNo THEN
    Result := -1;
    ROLLBACK;
    GOTO ENDOFFUN;
END IF;

-- 3. 单号递增
v_CurBillNo := v_CurBillNo + 1;

-- 4. 更新单号控制表
UPDATE tmm34_IdMaster
SET CurBillId = v_CurBillNo
WHERE IdTyp = IN_BILLTYPE;

-- 5. 生成单号（业务类型前缀 + 6位数字）
IF IN_BILLTYPE <> 'RQ' AND IN_BILLTYPE <> 'RS' THEN
    Result := IN_BILLTYPE || LPAD(TO_CHAR(v_CurBillNo), 6, '0');
ELSE
    Result := LPAD(TO_CHAR(v_CurBillNo), 8, '0');
END IF;
```

### 2.7 完整业务流程

#### 2.7.1 ITSM配件变更到维护入库完整流程

```
ITSM维护单配件更换完成
    ↓
写入SM_IN_PART_CHANGE
    ├─ sys_status = 2（已处理）
    ├─ operflg = 1（需入库）
    ├─ case_no = 工单号（如MD065202）
    └─ id = 自增ID（如25795）
    ↓
CCGL数据确认模块查询已处理记录
    ↓
用户点击"确认入库"
    ↓
更新SM_IN_PART_CHANGE.sys_status = 5（已作废手工）
    ↓
自动创建维护入库单
    ├─ 调用UF_GET_BILLNOU('IN')生成单号（如IN061790）
    ├─ 写入TWH13_IN
    │   ├─ inbillid = IN061790
    │   ├─ indate = SYSDATE
    │   ├─ whcd = 用户选择的仓库代码（如07）
    │   ├─ invtyp = '3'（维护类型）
    │   ├─ refbillid = '40699'（工单号的一部分）
    │   ├─ useflg = '0'（新建）
    │   └─ auditflg = '0'（未审核）
    └─ 写入TWH14_CHECKINDT（入库明细）
        ├─ inbillid = IN061790
        ├─ lineno = 1
        ├─ itemcd = 配件编码
        ├─ prddate = 生产日期
        └─ inqty = 入库数量
    ↓
更新TMM43_EID（工程师个人仓库设备表）
    ├─ 查询条件：eid = 配件序列号
    ├─ sflg状态变更（从工程师持有状态变为待检状态）
    ├─ whcd变更（从工程师仓库代码变更为用户选择的仓库代码）
    └─ qcflg = '待检'（质检标志）
    ↓
用户审核入库单
    ↓
更新TWH13_IN
    ├─ auditflg = '2'（已审核）
    ├─ auditman = 审核人
    ├─ auditdate = 审核日期
    └─ useflg = '1'（已入库）
    ↓
更新TWH11_DETAIL（批次库存表）
    ├─ 查询条件：itemcd = 配件编码 AND prddate = 生产日期 AND whcd = 仓库代码
    └─ itemqty = itemqty + 入库数量
    ↓
配件正式入库完成
```

#### 2.7.2 维护入库到维护出库完整流程

```
配件在仓库中（待检状态）
    ↓
质检人员领取配件进行质检
    ↓
质检通过
    ↓
配件移动到正式仓库（whcd变更）
    ↓
仓库管理员创建维护出库单
    ├─ 调用UF_GET_BILLNOU('OT')生成单号（如OT057374）
    ├─ 选择出库方式：optyp = 'ID'（EID出库）
    ├─ 选择仓库代码：whcd（如07）
    ├─ 选择设备：eid（如MT4A012153146）
    └─ 写入TWH15_OUT
        ├─ outbillid = OT057374
        ├─ outdate = SYSDATE
        ├─ whcd = 07
        ├─ invtyp = '3'（维护类型）
        ├─ optyp = 'ID'（EID出库）
        ├─ useflg = '0'（新建）
        └─ auditflg = '0'（未审核）
    ↓
写入TWH16_OUTDTEID（EID出库明细表）
    ├─ outbillid = OT057374
    ├─ lineno = 1
    ├─ itemcd = 配件编码
    ├─ prddate = 生产日期
    ├─ eid = 设备序列号
    ├─ outqty = 出库数量
    └─ qcqty = 质检数量
    ↓
用户审核出库单
    ↓
更新TWH15_OUT
    ├─ auditflg = '2'（已审核）
    ├─ auditman = 审核人
    ├─ auditdate = 审核日期
    └─ useflg = '1'（已出库）
    ↓
更新TMM43_EID（设备表）
    ├─ 查询条件：eid = 设备序列号
    ├─ sflg状态变更（从待检状态变为工程师持有状态）
    ├─ whcd变更（从正式仓库代码变更为工程师仓库代码）
    └─ opercd = 工程师代码
    ↓
更新TWH11_DETAIL（批次库存表）
    ├─ 查询条件：itemcd = 配件编码 AND prddate = 生产日期 AND whcd = 仓库代码
    └─ itemqty = itemqty - 出库数量
    ↓
配件出库给工程师完成
```

#### 2.7.3 关键数据流转

**refbillid字段作用**:
- **入库单（TWH13_IN）**: refbillid存储工单号的一部分（如40699对应工单MD040699）
- **关联方式**: 通过LIKE模糊匹配关联SM_IN_PART_CHANGE.case_no
- **SQL关联**: `WHERE SM_IN_PART_CHANGE.case_no LIKE '%' || TWH13_IN.refbillid || '%'`

**维护入库单与出库单关系**:
- **无直接关联**: 维护入库单与维护出库单之间没有直接关联
- **refbillid差异**: 维护出库单没有refbillid字段
- **独立操作**: 维护出库是独立的人工操作，不是自动触发

### 2.8 质检流程

#### 2.8.1 质检流程概述

**质检环节**: 配件入库后必须经过质检才能正式进入库存

**质检状态流转**:
```
配件入库（待检状态）
    ↓
质检人员从待检仓领取配件
    ↓
质检处理
    ↓
质检结果判断
    ├─ 质检通过
    │   ↓
    │   移动到正式仓库
    │   ↓
    │   更新TMM43_EID.qcflg = '合格'
    │   ↓
    │   可用于出库
    │
    └─ 质检不合格
        ↓
        移动到不合格品仓库
        ↓
        更新TMM43_EID.qcflg = '不合格'
        ↓
        返回供应商或报废处理
```

#### 2.8.2 质检涉及的表和字段

**TMM43_EID表质检相关字段**:

| 字段名 | 类型 | 说明 | 取值范围 |
|--------|------|------|---------|
| qcflg | CHAR(2) | 质检标志 | '待检'、'合格'、'不合格' |
| sflg | CHAR(1) | 设备状态 | 质检前后状态变更 |
| whcd | CHAR(2) | 仓库代码 | 质检前后仓库变更 |

**TWH01_WAREHOUSE表质检相关仓库**:

| 仓库代码 | 仓库名称 | 用途 |
|---------|---------|------|
| 04 | 待检仓 | 存放待检配件 |
| 01 | 成品仓 | 存放质检合格配件 |
| 02 | 维护仓 | 存放维护配件 |
| 其他 | 不合格品仓 | 存放质检不合格配件 |

#### 2.8.3 质检流程数据操作

**质检领取配件**:
```sql
-- 从待检仓查询待检配件
SELECT eid, itemcd, prddate, qcflg
FROM TMM43_EID
WHERE whcd = '04' AND qcflg = '待检';
```

**质检通过处理**:
```sql
-- 更新设备状态和仓库
UPDATE TMM43_EID
SET qcflg = '合格',
    sflg = '2',  -- 可用状态
    whcd = '01'  -- 移动到成品仓
WHERE eid = :ls_eid;
```

**质检不合格处理**:
```sql
-- 更新设备状态和仓库
UPDATE TMM43_EID
SET qcflg = '不合格',
    sflg = '9',  -- 不可用状态
    whcd = 'XX'  -- 移动到不合格品仓
WHERE eid = :ls_eid;
```

#### 2.8.4 质检与库存关系

**质检前**:
- 配件在待检仓（whcd='04'）
- qcflg='待检'
- 不计入正式库存（TWH11_DETAIL）

**质检通过后**:
- 配件移动到正式仓库（whcd='01'或'02'）
- qcflg='合格'
- 计入正式库存（TWH11_DETAIL.itemqty增加）

**质检不合格后**:
- 配件移动到不合格品仓
- qcflg='不合格'
- 不计入正式库存
