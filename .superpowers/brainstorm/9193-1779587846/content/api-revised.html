端点清单

方法 路径 用途 优先级

核心端点：POST /orders/batch

Request — 同一结构同时支持拆单和并单
{
  "orders": [
    {
      "suppliercd": "SUP001",
      "memo": "拆单-供应商A",
      "details": [
        {                     // 拆单：同一个ref
          "ref_pcplanid": "PP000180", "ref_pclineno": 1,
          "itemcd": "MB5000", "rgsqty": 60, "unitprice": 100
        }
      ]
    },
    {
      "suppliercd": "SUP002",
      "memo": "拆单-供应商B",
      "details": [
        {                     // 还是同一个ref → 自动拆
          "ref_pcplanid": "PP000180", "ref_pclineno": 1,
          "itemcd": "MB5000", "rgsqty": 40, "unitprice": 105
        }
      ]
    },
    {
      "suppliercd": "SUP003",
      "memo": "并单-合并三个部门的需求",
      "details": [
        {                     // 并单：不同ref → 自动并
          "ref_pcplanid": "PP000181", "ref_pclineno": 1,
          "itemcd": "MB5000", "rgsqty": 50
        },
        {
          "ref_pcplanid": "PP000182", "ref_pclineno": 1,
          "itemcd": "MB5000", "rgsqty": 30
        }
      ]
    }
  ]
}

后端校验逻辑（单次数据库事务）

1. 结构校验 → orders 数组非空，每项有 suppliercd + details
2. 聚合校验 → 按 (pcplanid, pclineno) 汇总所有 detail 的 rgsqty
3. 余额校验 → 汇总 qty ≤ get_available_qty()
4. UK 冲突检查 → 查询 TPC20 是否已有相同关联
5. 事务写入 → FOR UPDATE 锁定需求行 → 写 tpc12/tpc13 → 写 TPC20 → COMMIT

⚠️ 关键：步骤 4-5 之间用 SELECT ... FOR UPDATE 防止并发超量
