前端交互架构（修订版）

拆单入口：订单创建页 | 并单入口：智能扫描（自动识别）

场景A：拆单 — 订单创建表单
入口：PurchaseRegisterList → 【新建订单】

Step 1：选择需求单 PP000180
└─ 显示明细：电源 × 100

Step 2：分配到供应商
├─ 默认：100个 → [供应商下拉]
└─ 点击[拆单] → 新增一行
   ├─ 60个 → SUP001
   └─ 40个 → SUP002

Step 3：实时校验 + 后端 validate

Step 4：POST /orders/batch
场景B：并单 — 智能扫描
入口：PurchasePlanList → 【智能合并】

Step 1：后端自动扫描
├─ auditflg='2'（已审核）
├─ available_qty > 0
└─ 按 itemcd 分组聚合

Step 2：弹窗展示分组结果
├─ [✓] 电源：3个需求 / 100个 → 推荐供应商
├─ [✓] 网线：2个需求 / 50个 → 推荐供应商
└─ ○ 显示器：仅1个需求（无可合并）

Step 3：用户确认 → POST /orders/batch

API 调整：merge-preview 无需入参

文档方案需要前端传 pcplanids 数组，智能扫描方案改为：

POST /requisitions/merge-preview（无参或空 body）
→ 后端自动查 auditflg='2' AND available_qty > 0 的所有需求行
→ 按 itemcd 分组 → 过滤出 count ≥ 2 的"可合并组"和 count = 1 的"无可合并组"
→ 推荐供应商来源：tip02_supplier_price 表（已有）
