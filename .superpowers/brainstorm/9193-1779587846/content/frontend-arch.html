前端交互架构

拆单和并单的入口不同，但最终都调用同一个 API

拆单流程：从订单创建页进入

入口：PurchaseRegisterList.vue → 【新建订单】按钮
页面：订单创建表单（已有），新增"选择需求"功能

┌─ Step 1：选择需求单 ─────────────────
│ 下拉选择 PP000180，显示明细：电源 × 100
│
├─ Step 2：分配到供应商 ──────────────
│ 默认：100个 → 供应商下拉选择
│ 点击[拆单]：新增一行 → 60个→SUP001 / 40个→SUP002
│ 前端实时校验：分配总量 ≤ 可用数量
│
├─ Step 3：调 validate API ─────────────
│ 后端二次校验，返回 available_qty vs requested_qty
│
└─ Step 4：调 POST /orders/batch ─────
一次性提交所有分组，后端事务写入

→ 组件位置：新建/复用订单创建弹窗，不放在列表页

并单流程：从需求列表页进入

入口：PurchasePlanList.vue → 勾选 + 【合并生成订单】按钮

┌─ Step 1：勾选需求单 ─────────────────
│ [✓] PP000180 [✓] PP000181 [✓] PP000183
│
├─ Step 2：调 merge-preview API ──────
│ 后端按 itemcd 分组 → 推荐供应商 + 汇总数量
│
├─ Step 3：用户确认/调整 ──────────────
│ 预览弹窗：电源×100→SUP001 / 网线×20→SUP003
│ 可修改供应商、调整数量
│
└─ Step 4：调 POST /orders/batch ─────
前端将 preview groups 转换为 orders 数组，统一提交

→ merge-preview 只管查询+建议，不写数据
